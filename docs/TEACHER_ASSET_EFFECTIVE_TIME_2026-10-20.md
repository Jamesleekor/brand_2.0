## 동작

교사 경제 현황 → 학급 운영의 자산 지급·차감에서 현재 시각 / 직접 지정 / 어제를 선택한다. BV·GOLD·CRYSTAL의 지급과 차감, BV+GOLD 동시 처리에 모두 적용된다. 날짜·시간은 브라우저 시간대와 관계없이 한국시간이며 분 단위다. 성공 후 현재 시각 모드로 초기화해 다음 작업에 소급 날짜가 남지 않도록 했다.

새 거래는 처음 INSERT할 때 `created_at`을 선택한 반영 일시로 기록한다. `recorded_at`은 서버의 실제 처리 시각이다. 과거 거래를 UPDATE하지 않으며 기존 거래의 `recorded_at`은 NULL 상태로 유지해 과거 처리 시각을 새로 꾸며내지 않는다. NULL은 화면에서 기존 `created_at`으로 표시한다. 과거 시점 지갑 잔액을 다시 만드는 기능은 아니며 `balance_after`는 실제 처리 후 잔액이다.

현재 지갑·티어는 실행 즉시 변경된다. 세율·감면·미납금·입찰 예약 등은 현재 상태를 기준으로 기존 함수를 그대로 사용한다. 부분 납부로 발생한 미납금의 부과 일시도 지정 일시로 기록하고 실제 처리 시각을 별도로 남긴다. 기존 미납금 자동 상환 거래는 실제 상환일을 유지한다.

## 통계 연결

MVP·월간 BV·신용도·경제 히스토리는 기존 거래 날짜 인덱스와 집계를 그대로 사용하므로 새 거래가 지정 일시에 귀속된다. 영향을 받는 계산 완료 DRAFT MVP 회차는 같은 원자적 작업에서 자동 재계산하며 교사 평가·후보·메모를 보존한다. UI는 MVP 보드·상세·목록, 자산·히스토리·거래 취소 캐시를 갱신한다. 확정된 MVP 기록은 수정하지 않는다. 다른 기능의 이미 확정된 스냅샷을 다시 쓰는 기능은 아니다.

미래 예약은 지원하지 않으며 현재 시각 이후 입력을 서버에서 거절한다. 명시적으로 지정한 일시가 1.0 원장 이관 완료 기간 또는 확정 MVP의 평가·비교 기간에 속하면 거절한다. 현재 학급의 이관 기준으로 2026-09-01부터 지정 가능하다.

히스토리는 반영 일시로 날짜 필터링·정렬한다. 실제 처리일이 다르면 두 시각을 함께 표시한다. 최근 거래 취소 패널은 거래 ID 역순으로 조회하여 어제 날짜로 방금 처리한 거래도 최근 목록에서 볼 수 있다.

## 서버 구조와 권한

기존 `teacher_adjust_student_assets_v2`, `teacher_adjust_student_assets_combined`, `create_transaction` 및 지급·차감 helper signature·정의·ACL은 보존했다. 새 `teacher_adjust_student_assets_at`, `teacher_adjust_student_assets_combined_at` RPC는 별도 이름으로 추가해 overload 충돌을 피했다.

새 RPC는 로그인과 교사 권한·학급을 검사하고 기존 검증된 조정 함수를 호출한다. 원장 INSERT 이전 트리거가 반영 일시를 설정하므로 학기 자동 배정·후속 트리거에도 처음부터 같은 일시를 사용한다. 컨텍스트는 현재 SQL 트랜잭션 안에서만 사용하며 성공·실패 모두 기존 값으로 복구한다. 지정 일시는 직접 교사 조정(source_id NULL)과 같은 학급의 미납금 부과에만 적용한다. 일반 일일퀘스트·뉴비 지급·다른 학급·자동 상환·역거래에는 전파하지 않는다.

내부 helper 3종의 PUBLIC/anon/authenticated EXECUTE를 회수했다. 외부 RPC 2종은 authenticated EXECUTE와 SECURITY DEFINER를 의도적으로 사용하는 교사 API다. 보안 진단에는 이 신규 RPC 2종의 authenticated SECURITY DEFINER 노출 안내가 추가되며, 내부 교사·학급 검사와 내부 helper 비공개를 확인했다. 별도 공개 테이블·RLS 변경이나 광역 GRANT는 없다.

## 검증

- 새 날짜 트리거를 동일 함수가 연결된 임시 행 11개에 적용: 직접 지급·차감 3종, 자동 상환, 일일퀘스트, 다른 학급, 뉴비 지급, 역거래, 현재 시각 기본값, 미납 부과 학급 경계 통과. 실제 학생·지갑 거래를 테스트로 만들지 않았다.
- 변경 TS/TSX 7개 TypeScript 5.6.3 구문 검사 통과. 한국시간 변환·자정 경계·윤년·잘못된 날짜 등 8개 사례 통과.
- 실제 Zod 스키마의 날짜·단일/동시·중복 학생·금액·기존 API 호환 15개 입력 사례와 확장 히스토리 쿼리 EXPLAIN 계획 검사 통과.
- 실제 기존 거래·미납금(새 NULL 열 제외)·전체 지갑·MVP 회차 해시 불변 확인.
- 기존 단일·동시 조정 및 create_transaction 함수 MD5 불변 확인. 전날 적용한 MVP 뉴비 BV 제외 정책도 보존 확인.
- npm 설치·build·dev, Git commit/push, 실제 교사 로그인 지급·차감 E2E는 실행하지 않았다.

## 사용자 확인

1. 원클릭 프론트 패치 적용 후 프로젝트 폴더에서 `npm run build` 실행.
2. 테스트 계정 하나를 선택하여 어제 날짜·시간으로 소액 BV 지급/차감 및 GOLD·CRYSTAL·동시 처리를 확인한다.
3. 거래 히스토리의 반영 일시/실제 처리 일시와 최근 취소 목록을 확인한다.
4. 미확정 MVP 초안과 해당 기간의 획득·차감·순증 BV 및 성장률을 확인한다.
5. 현재 시각 모드, 미래 입력 거절, 실패 시 모달 내부 오류, 성공 후 날짜 초기화, 세금과 미납금 경로를 확인한다.

서버는 이미 적용되어 있다. SQL을 다시 실행할 필요가 없다. 기존에 오늘 날짜로 이미 지급한 거래를 옮기는 기능은 이번 범위에 포함하지 않는다.
