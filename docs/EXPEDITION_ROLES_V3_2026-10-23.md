# 편린 원정 역할 슬롯과 적합도 V3

## 적용 상태

2026-10-23 운영 DB에 계산 함수·주차 생성·공개 함수와 버전 제약을 적용했다. 처음 migration 도구 요청은 응답 대기 중 중단됐고 반영되지 않았음을 조회로 확인했다. 이후 SQL 트랜잭션으로 적용하고 실제 함수 정의를 다시 확인했다. 실행 SQL은 `supabase/APPLY_EXPEDITION_ROLES_V3_20261023.sql`이다. 이 SQL은 이미 운영에 적용했으므로 전달받은 CMD 실행 후 다시 실행할 필요가 없다.

이번 주(10/19 시작) 실제 학급 원정은 이미 13건 출발했으므로 기존 V2를 유지한다. 새 역할 보너스는 **10/26 시작 주차, 즉 10/30 금요일 원정부터** 적용한다. 기존 주차·출발·보상·멤버 스냅샷을 UPDATE하지 않았다. UI는 배포 즉시 역할별 이미지 슬롯을 제공하고 이번 주에는 보너스 유예 안내를 표시한다.

## 역할과 계산

- 첫 번째 원정대장: 해당 편린의 유효 주·부 상성 점수 기여를 1.2배로 계산한다.
- 두 번째 부대장: 탐사지 원정 특기 일치 시 기존 특기 보너스와 별도로 적합도 +5%p.
- 세 번째 대원: 기존 기여만 반영한다.
- 기본식은 주성분 70 × min(합/14,1.2), 부성분 30 × min(합/8,1.2), 기존 특기 min(일치 인원 ×5,10)이다.
- 속성 성분별 기존 상한을 유지하고 최종 적합도는 130%를 넘지 않는다. 반올림 후 실제로 더해진 정수 %p를 기본·대장·부대장으로 분해해 표시하므로 표시 합계가 최종값과 같다. 상한 때문에 +5%p를 모두 받지 못하면 안내한다.
- 버전 `ELEM_70_30_ROLES_V3`에서만 역할 효과를 활성화한다. V1/V2의 계산·순서 무관성은 유지한다.

## 편성 UI

대장·부대장·대원 3칸에 역할명, 편린 이미지/이모지, 이름과 효과를 표시한다. 편집할 역할 칸을 누른 뒤 아래 편린을 누르면 배치한다. 최초 편성은 다음 빈칸으로 자동 이동한다. 이미 선택된 편린을 다른 칸에 넣으면 두 칸을 교환한다. 좌우 화살표로도 교환하며, 해제는 해당 칸만 비워 다른 역할이 이동하지 않는다. 제출 중 편성 편집을 막는다.

역할 슬롯은 적합도 sticky 요약 밖에 두어 모바일에서 고정 패널이 지나치게 커지지 않게 했다. 3칸은 작은 화면에서도 같은 행에 표시한다. 이미지 실패 시 이모지로 대체한다. 과거 V1/V2 결과에는 대장 역할을 소급 표시하지 않는다.

미리보기 캐시 키에 주차·계산 버전·회차·탐사지·**선택 순서**를 포함한다. 기존의 ID 정렬을 제거했다. 순서 변경 시 새 서버 미리보기를 요청하며 실패 또는 계산 중에는 제출을 막는다. 주차/회차 전환 시 편성을 초기화한다.

## 검증

- Node 역할 검사: 같은 3명의 6개 배치, V1/V2 보존, 특기 중첩, 130 상한, 중복/미완성 편성, 배치/교환/해제/빈칸 보존 통과.
- 서버: 변경 DDL과 새 SQL 검사를 하나의 트랜잭션에서 실행한 뒤 롤백했다. 6개 배치 결과 96/91/92/92/88/93%, 기존 기본값 85%, 서버·클라이언트 일치 확인. 다음 주 생성·공개 및 설정 스냅샷도 확인했다.
- 기존 SQL 상성 회귀검사 26개, 기존 Node V2 상성/fixture 검사 통과.
- 수정 TS/TSX 5개 파일의 TypeScript 구문 검사 통과. 전체 타입 검사 및 production build는 실행하지 않았다.
- 브라우저 시각 검증은 Chromium 실행 파일이 없어 완료하지 못했다. Windows CMD 실제 더블클릭·사용자 로컬 build·실제 로그인 UI E2E는 사용자 적용 후 확인 대상이다.
- npm 설치/build, Git commit/push는 실행하지 않았다. 기존 public RPC와 private scheduler 함수의 권한·시그니처를 유지했다.

## PC 적용

다운로드한 `BRAND_EXPEDITION_ROLE_SLOTS_V3_20261023.cmd`를 더블클릭한다. 기본 경로 `C:\brand_2.0\brand_2.0`을 인식한다. 사용자 홈의 brand-patch-backups 아래 원본을 보관하고, 기존 파일은 변경 구간만 적용하며 새 컴포넌트·검사·설명 파일을 추가한다. 다른 로컬 수정이 변경 구간과 충돌하면 쓰기 전에 중단한다. 재실행은 안전하다.

적용 후 로컬에서 `npm run build`를 실행하고 기존 방법으로 배포한다. 순서 교환 후 이미지와 적합도 갱신, 중간 칸 해제 시 나머지 역할 보존, 모바일 3칸 표시, 기존 결과 보존을 확인한다.
