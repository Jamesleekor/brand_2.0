# 편린 영입 조건 확장

기준: 2026-10-09 KST. 운영 DB 구조를 직접 조사한 후 기존 RPC를 증분 확장했다.

## 조건과 계산 기준

기존 총 업적 수·등급별 업적 수·티어 이상 조건에 다음 네 종류를 추가했다.

| 조건 | 코드 | 판정 |
|---|---|---|
| 특정 편린 모두 보유 | OWNED_CHARACTERS | 이름/UID 검색으로 선택한 모든 편린을 현재 보유 |
| 전체 편린 보유 수 | OWNED_CHARACTER_COUNT | 해당 학급의 현재 보유권 수 >= 설정값 |
| 전체 편린 보유 가치 | OWNED_CHARACTER_VALUE | CRYSTAL 영입 편린의 현재 기본 가격 합계 >= 설정값 |
| 완성 콜렉션 수 | COMPLETED_COLLECTION_COUNT | 현재 완성한 공개·활성 콜렉션 수 >= 설정값 |

- 회수된 편린은 제외한다. 장착 여부는 무관하다.
- 보유 수는 무료/이벤트 편린도 포함하며, 비활성화된 편린이라도 보유권이 유지되면 기존 수집 랭킹과 동일하게 계산한다.
- 가치는 기존 수집 랭킹과 같은 기준이다. 할인/실지불액/공명력을 사용하지 않는다. FREE/EVENT_ONLY/TEACHER_ONLY/UNAVAILABLE 또는 가격 설정이 없는 편린은 0이다.
- 값은 실시간 판정이며, 현재 기본 가격이 바뀌면 보유 가치 판정도 바뀐다.
- 콜렉션 완성 판정은 기존 character_collection_is_complete를 재사용한다. 숨김·중지 콜렉션, 구성원이 없는 콜렉션은 수에 포함하지 않는다.
- 선택한 편린의 ID를 character_requirements.metadata.required_character_ids에 저장한다. 이름이 바뀌어도 동일 편린을 참조한다.
- 자기 자신, 중복/존재하지 않는 편린, 빈 선택은 거부한다. 신규 선택은 활성 편린만 가능하며 기존 비활성 참조는 재저장할 수 있다.
- 동일 그룹 내 AND, 그룹 간 OR는 유지한다. 특정 편린 중 하나만 요구하려면 각각 별도 OR 그룹에 넣는다.
- 네빌 CHAR-081은 추가돼 있지만 조건은 확정하지 않았으므로 기존 DRAFT/NONE 정책을 유지했다.

## 설정 위치

교사 편린 운영 → 편린 Master → 대상 편린의 영입 조건 → 조건 그룹.

조건 종류를 선택해 숫자를 입력하거나, '특정 편린 모두 보유'에서 이름을 검색하고 체크한다.
학생 표시용 문구를 비워두면 선택한 이름과 숫자로 자동 생성한다. 직접 작성한 문구는 보존한다.
저장 오류는 모달 안에도 표시하며, 저장 성공 시 교사 영입 패널과 학생 영입 스토어 캐시를 무효화한다.

## DB 적용

운영 DB에 migration character_recruitment_collection_requirements(20261008154249)를 적용했다.
소스: supabase/migrations/20261008154249_character_recruitment_collection_requirements.sql.
재적용할 필요는 없다. 기존 함수 signature/default parameter와 ACL을 유지했다.
내부 판정 함수는 anon/authenticated에 노출하지 않았다. 교사 RPC는 기존 학급/역할 검증을 유지한다.
학생의 recruit_character가 같은 내부 판정을 호출하므로 브라우저 표시만 우회해서 영입할 수 없다.
새 테이블, enum, 데이터 초기화 또는 소유권/자산 변경은 없다.

## 검증

- 기존 조건 2,005건의 판정이 변경 전후 모두 동일했다.
- 정책 84행, 그룹 82행, 조건 102행, 보유권 429행이 변경 없이 유지됐다.
- SQL Editor-safe 테스트 392건 통과: 수/가치/콜렉션 수의 정확한 경계와 +1, 선행 편린 모두 보유/하나 미보유/빈 선택/잘못된 데이터, AND 실패/OR 대안 충족, 내부 함수 ACL.
- 테스트는 트랜잭션 안에서 임시 조건을 구성하고 전부 ROLLBACK했다. 학생 자산과 보유권은 수정하지 않았다.
- 두 RPC/스키마 TypeScript 파일은 Node 내장 TypeScript parser/JavaScript 구문 검사 통과. git diff --check 통과.
- 교사 UI TSX와 RPC·Zod 스키마 TS 파일 3개는 tree-sitter TypeScript/TSX 구문 검사에서 오류 0건.
- npm 설치·production build·dev 서버는 저장소 규칙에 따라 실행하지 않았다.
