## 1. 기준 자산과 적용 원칙

승인된 시안 (이미지 2장. 구현 담당에게 함께 전달한다):

- 크롬북 시안 — 1366×768
- 모바일 시안 — 너비 390px, 스크롤 전체

HTML 시안은 없다. 시안의 숫자·출석·요일별 결과는 모두 예시다. 운영 화면에 그대로 넣지 않는다.

화면의 기본 구조·색상·밀도는 시안을 유지한다. 중간 너비에서 열이 찌그러지는 것을 방지하기 위한 반응형 구간과 기록 상태의 정확한 문구는 이 명세를 따른다. 시안에 없는 휴업일 표시(달력 `—`, 주간표 `휴업` 열)는 5.2·7장을 따른다. 시안 범례의 `— 운영 없음`은 `— 휴업`으로 쓴다. 이 문서는 사용자 요청과 저장소 AGENTS.md의 적용을 전제로 한다.

### 변경하지 않는 영역

- 기존 승인·회수된 업적과 과거 월간 확정 스냅샷.
- 학생의 체크값, 출결, 거래, 원장 생성·정산 상태.

- 기존 출석 체크·일퀘 원장 자동 생성·보상 로직. 새 휴업일 테이블과 연결하지 않는다.

화면 조회 과정에서 원장 생성·정산·보상 함수, 출석 체크 함수, 재계산으로 저장하는 함수를 호출하지 않는다.

## 3. 화면의 전체 구조

창 제목: `출석 · 일일퀘스트 기록`.

크롬북에서는 위에서 아래로 다음 순서다.

1. 제목과 닫기 버튼.
2. 연속 출석 / 선택 주 전체 완료 / 선택 주 퀘스트의 요약 카드 3개.
3. 왼쪽 월간 달력, 오른쪽 선택 주 상세표.
4. 상세표 아래 선택 날짜의 미달 항목 또는 상태.
5. 관련 업적 안내 카드.
6. 하단 접이식 출석 마일스톤·보상 내역.

모바일에서는 요약 카드 2개 → 달력 → 주간표 → 선택일 상세 → 업적 안내 → 접이식 내역 순서다. 모바일에서 생략한 세 번째 요약 카드의 완료/확정 항목 수는 주간표의 보조 설명에서 확인할 수 있게 한다.

새 페이지로 이동시키거나 별도 메뉴를 추가하지 않는다. 홈 버튼 아이콘은 유지하고, 라벨이 표시되는 곳은 `출석·일퀘`로 줄일 수 있다. 접근성 이름은 전체 제목을 사용한다.

## 4. 반응형 치수와 표 규격

### 4.1 구간별 배치

| 항목 | 크롬북·데스크톱 ≥1024px | 중간 화면 701~1023px | 모바일 ≤700px |
|---|---|---|---|
| 창 너비 | 최대 960px, 뷰포트 내 여백 확보 | 최대 640px, 한 열 | 화면 가용 너비 전체 |
| 내부 좌우 여백 | 22px | 18px | 14px |
| 본문 구성 | 달력 380px + 간격 18px + 상세표 가변 | 달력·표 세로 배치 | 달력·표 세로 배치 |
| 요약 카드 | 동일 폭 3개 | 동일 폭 2개 | 동일 폭 2개 |
| 주간표 항목 열 | 86px | 86px | 76px |
| 주간표 요일 열 | 남은 폭을 5등분 | 남은 폭을 5등분 | 남은 폭을 5등분 |
| 스크롤 | 높이 부족할 때 창 내부 세로 스크롤 | 창 내부 세로 스크롤 | 창 내부 세로 스크롤 |

- 모바일에서 본문을 축소 배율로 줄이지 않는다. 하나의 6열 표를 유지한다.
- 데스크톱은 뷰포트 높이에 맞춰 max-height를 설정한다. 모바일은 안전영역(safe-area)과 dvh를 고려하고, 배경 페이지는 고정한 채 모달 내부에서 세로로 스크롤한다. 임의로 스크롤바를 전역 숨김 처리하지 않는다.
- 표·카드 컨테이너에는 `min-width:0`을 적용한다.
- 표는 `width:100%; table-layout:fixed; border-collapse:collapse`를 기본으로 하고 colgroup으로 첫 열을 고정한다.
- 셀의 가로 padding은 기본 2px, 항목 열 왼쪽 padding은 10~12px다. 텍스트 길이에 따라 열 폭이 달라지지 않는다.
- 360px 화면에서 가용 표 너비 약 330px, 항목 76px, 요일 약 51px가 기준이다. 390px에서는 요일 약 57px다. 테두리 반올림 차이는 허용한다.
- 표를 `justify-between`으로 흩어진 여러 행처럼 구현하지 않는다. 모든 행의 같은 요일 중심선이 일치해야 한다.
- 크롬북 검증은 물리 화면 해상도가 아니라 브라우저 콘텐츠 뷰포트를 측정한다. 1366×768 뷰포트와 1366×640 뷰포트를 따로 확인한다. 6주 달력·오류 문구·글자 확대에서는 내부 세로 스크롤을 허용하며, 한 화면에 넣기 위해 글자를 줄이거나 날짜 행을 숨기지 않는다.

### 4.2 줄바꿈·글자·조작 영역

| 요소 | 규칙 |

| 날짜/개수/상태 | `11.10`, `4/4`, `완료`, `미달`, `대기`는 줄바꿈 금지 |

| 조작 버튼 | 보이는 화살표는 작게 유지하되 실효 터치 영역 최소 44×44px. 인접 버튼 영역이 겹치지 않아야 함 |

다크 배경에서 아이보리 본문, 민트 완료, 살구색 미달, 연보라 대기, 금색 선택 강조를 사용한다. 의미가 있는 본문을 흐린 회색으로 처리하지 않는다. 실제 대비를 확인한다.

### 4.3 기존 공통 모달과의 통합 — 반드시 먼저 적용

현재 공통 Modal은 md 약 448px / lg 약 512px / wide 최대 1180px 및 86dvh 제한을 사용한다. 바깥 px-4와 본문 p-4도 기본이다. 따라서 기존 size를 바꾸거나 본문에 시안 HTML을 넣는 것만으로 960px 시안이 재현되지 않는다.

- 기록 창 전용으로 선택 가능한 variant 또는 명시적 크기/본문 padding prop을 추가한다. 다른 모달의 기본값은 변경하지 않는다.
- 데스크톱 최대 960px, 모바일 외곽 여백 0, 본문 여백 14px를 최종 계산값으로 맞춘다. 공통 p-4와 기능 내부 padding을 이중 적용하지 않는다.
- 제목은 공통 헤더 또는 전용 헤더 중 한 곳에만 둔다. 이중 제목과 닫기 버튼이 생기면 실패다.
- 스크롤은 모달 본문 1곳만 담당한다. `min-height:0`, `overflow-y:auto`, 헤더 `flex-shrink:0`을 확인한다. 본문 안에 또 max-height 스크롤을 만들지 않는다.
- 기존 Modal은 ESC/focus trap/body scroll lock을 완성한 컴포넌트라고 가정하지 않는다. 실제 코드를 확인하고 전용 variant에 필요한 기능을 추가한다. 공통 수정 시 다른 모달 회귀 검증을 포함한다.
- 날짜 셀은 최소 높이 48px, 인접 셀 사이 4px 이상을 유지한다. 날짜 칸 너비 전체가 클릭 영역이며 숫자만 작은 버튼으로 만들지 않는다.
- 월/주 화살표는 실제 44px 버튼으로 배치하고 아이콘만 작게 한다. 보이지 않는 hit-area를 옆 버튼으로 확장하지 않는다.
- 최소 너비 360px에서 헤더 높이 약 44px는 요일 날짜 2줄로 의도된 것이다. 그 외 표 본문은 한 줄이다.
- 범례는 여러 개의 짧은 항목으로 줄바꿈할 수 있다. 범례 전체를 nowrap으로 고정하지 않는다. 각 항목 내부만 한 줄로 유지한다.

## 5. 시간·기간·선택 동작

### 5.1 상태와 날짜 계산

- 날짜 기준은 서버의 Asia/Seoul `kst_today`다. 서버는 요청 내 기준시각을 한 번만 확정하고 파생 날짜를 계산한다.
- 퀘스트 날짜는 `quest_date`를 따른다. 생성·정산 timestamp로 날짜를 재분류하지 않는다.
- `viewMonth`와 `selectedDate`를 기본 상태로 두고 `selectedWeekStart`는 선택일에서 파생한다. 세 상태를 서로 독립적으로 갱신하지 않는다.
- 첫 열기는 오늘이 속한 월·오늘 날짜·오늘의 ISO 주다. 오늘이 조회 범위(11.1) 밖이면 가장 가까운 범위 끝 날짜(학기 종료 후에는 2027-01-05)로 연다. 다시 열어도 기본은 오늘이다. 창이 열린 동안에만 사용자의 탐색 위치를 유지한다.
- 달력은 일~토, 주간 상세표는 해당 ISO 주의 월~금이다. 날짜는 YYYY-MM-DD로 저장한다.
- `new Date('YYYY-MM-DD')`의 로컬 변환이나 ISO 주 번호만으로 계산하지 않는다. 연도 포함 civil date 연산을 사용한다. 월 범위는 월초 이상·다음 월초 미만, 주 범위는 월요일 이상·다음 월요일 미만이다.

### 5.2 클릭과 이동 규칙

- 달력 날짜 클릭: 선택일·선택 주·표 강조·요약·상세를 함께 갱신한다. 현재 표시된 달의 범위 안에서 미래 평일도 조회 가능하지만 기록 대신 `예정`이다.
- 주간표의 요일/날짜 머리도 클릭·키보드로 날짜를 선택할 수 있게 한다. 표 결과 셀을 눌러도 그 열의 날짜를 선택할 수 있다. 모바일에서 실패 날짜를 보기 위해 달력까지 다시 올라갈 필요가 없어야 한다.
- 선택한 표 날짜가 다른 달이면 그 날짜가 속한 달로 이동한다. 선택일이 없는 표 상태나 같은 일자 숫자끼리 잘못 강조되는 일을 막는다.
- 월 이동: 사용자가 의도한 일자 preferredDay를 보존하며 대상 말일로 clamp한다. 1/31→2/28→3/31이 되어야 한다. 현재 월로 돌아올 때 그 일자가 오늘 이후면 오늘로 제한한다. 이 제한 때문에 preferredDay를 덮어쓰지 않는다.
- 주 이동: 선택일을 ±7일 이동하여 요일을 보존한다. 미래 주로 이동하는 것은 차단하고 현재 주로 진입할 때 선택일이 오늘 이후면 오늘로 제한한다. 실제 날짜를 직접 선택하면 preferredDay는 갱신한다.
- `오늘` 버튼은 월/선택일/주를 서버 오늘로 함께 복귀시킨다. 조회 범위(2026-08-24~2027-01-05) 밖으로 가는 월/주 버튼은 비활성화한다. 범위 밖 날짜(8/1~8/23, 1/6 이후)는 버튼이 아니며 흐린 `—`로 둔다.
- 주 제목은 `11.9~11.13`; 달을 넘으면 `11.30~12.4`, 연도를 넘으면 `2026.12.28~2027.1.1`로 표시한다. 긴 표제는 줄바꿈 가능한 보조 행에 연도를 나누되 날짜 토큰 자체를 끊지 않는다.
- 휴업일 선택: 주말·공휴일·학교 휴업일은 일일퀘스트 기록 조회 대상이 아니다.
  - 평일 휴업일(예: 9/25 추석): 주간표에서 그 열의 모든 행을 `휴업`으로 표시한다.
  - 주말: 월~금 표에는 선택 열이 없으며 그 ISO 주를 보여준다. 주말을 다음 주 월요일로 임의 이동시키지 않는다.
  - 선택일 상세에는 `9.25 금요일 · 휴업일(추석)` 또는 `11.15 일요일 · 주말`과 주말 접속 출석 여부만 표시한다. 그날 자동 생성된 미확정 원장의 체크는 보여주지 않는다.
- 월 달력의 앞뒤 빈 칸은 버튼이 아니다. 4·5·6주 높이를 모두 허용하고 주간표 세로 크기를 억지로 늘려 맞추지 않는다.

### 5.3 모바일 이동과 강조

- 달력 아래 `선택 주 상세 보기 ↓`, 표 근처 `달력으로 ↑`를 제공한다. 자동 강제 스크롤 대신 사용자가 이 버튼을 눌렀을 때만 이동한다.
- 날짜 선택은 한 개의 금색 강조, 선택 주는 약한 배경으로 표시한다. 오늘은 작은 점 또는 별도 링과 aria-current=date로 구분한다.
- 월/주 이동 시 모달 전체 scrollTop을 매번 0으로 만들지 않는다. 표에서 이동했다면 표 헤더가 시야에서 사라지지 않도록 유지한다.
- 한국시간 자정이 지나면 다음 visibility/focus/사용자 조작 시 서버 오늘을 갱신한다. 탐색 중인 과거 월은 유지하며, 이전 오늘을 선택 중이었다면 새 오늘로 전환한다. 화면 비활성 상태에서 반복 타이머로 요청하지 않는다.

## 6. 집계의 기본 단위

| 표시 순서 | quest_code | 화면 라벨 |
|---:|---|---|
| 1 | ATTENDANCE | 출석 |
| 2 | PRIMARY_JOB | 1인1역 |
| 3 | LEARNING_MATERIALS | 준비물 |
| 4 | CLEANING | 청소 |

퀘스트의 출석 PASS와 학교 출결의 출석 인정은 서로 다른 정보다. 달력 날짜 옆 출석 기호는 attendances의 인정 상태를, `n/4`와 상세표 출석 행은 퀘스트 체크를 따른다. 서로 값을 대신 채우지 않는다.

출석 인정은 기존 운영 기준인 PRESENT·LATE·EXCUSED를 따른다. 상세 선택일에는 실제 상태를 한글로 구분한다. ABSENT는 결석이다. 출결 행이 없다는 이유로 결석으로 만들지 않는다.

출결 행이 없는 날의 표시 (v1.3, 담임 결정):

- 결과가 확정된 운영일(정산된 원장 또는 13.2 보관 테이블)인데 출결 행이 없으면, 그날 일일퀘스트 `출석` 항목 결과로 달력의 출석 표시를 정한다. 해당 날짜: 8/24~9/1 전체, 9/2, 9/18, 9/21, 9/22, 9/23, 9/29, 9/30.
- PASS → 달력 `✓`, 상세 `출석 인정 (일일퀘스트 기준)`. FAIL → 달력 `✓` 없음, 상세 `일일퀘스트 출석 미달`. `결석`이라고 쓰지 않는다.
- 응답에는 attendance_source=DAILY_QUEST_FALLBACK으로 구분한다. 실제 출결 행이 있으면 항상 그 행이 우선이다.
- 이 규칙은 기록 창 표시에만 쓴다. 현재 연속 출석·누적 출석·마일스톤 숫자는 기존 RPC 값을 그대로 쓰며 바뀌지 않는다. attendances에 행을 만들지 않는다.
- 결과가 확정되지 않은 날에 출결 행이 없으면 출결 문구를 생략한다.

주말 접속 출석(record_source=WEEKEND_APP_ACCESS)은 집에서 웹앱에 접속하면 자동 기록되는 출석으로, 월 3·7·14·28일 출석 마일스톤 보상에 쓰인다. 달력의 주말 칸에 출석 기호 `✓`를 표시하고, 상세에는 `주말 접속 출석`으로 쓴다. 퀘스트 결과는 표시하지 않는다.

교사 계정과 테스트 계정(is_test_account=true)은 이 기록 창의 조회 대상이 아니다. 같은 학급에 있어도 학생 집계에 넣지 않는다.

연속 출석·누적 출석·마일스톤의 공식 숫자는 기존 RPC 결과를 재사용한다. 달력에서 개수를 세어 별도 연속 출석 공식을 만들지 않는다.

## 7. 날짜별 상태 결정

v1.2에서 상태를 9개에서 6개로 줄였다. 휴업일 테이블(13.1)이 생겨 `운영하지 않음`과 `기록 불명확`을 추측으로 구분할 필요가 없어졌고, DB 제약(2장) 때문에 중복 체크·알 수 없는 코드는 생길 수 없다. 조회 범위를 2학기로 고정하여(11.1) 구버전 이력 상태도 필요 없다.

| 상태 | 판정 기준 | 달력 표시 | 주간표/상세 |
|---|---|---|---|
| CLEAR | 결과 확정 + 4종 모두 PASS | `4/4` 민트 | 체크 4개, 전체 완료 `완료` |
| PARTIAL | 결과 확정 + FAIL ≥1 | `n/4` 살구색 | PASS `✓`, FAIL `✕`, 전체 완료 `미달` |
| PENDING | 운영일인데 원장이 DRAFT/SUBMITTED/RETURNED, 또는 오늘인데 원장이 아직 없음 | 오늘 `대기`, 지난 날짜 `미확정` | 정산 전이라는 의미이며 확정 집계 제외 |
| FUTURE | 오늘 이후의 운영일 | `예정` | `예정` |
| CLOSED | 주말, 휴업일 테이블에 있는 날, 조회 범위 밖, 재학 기간 밖 | `—` (주말 접속 출석이 있으면 `✓`만 함께) | 평일 휴업일 열은 `휴업`. 범위·재학 기간 밖은 흐리게 |
| CHECK_NEEDED | 지난 운영일인데 원장이 없음, 또는 확정 원장인데 본인 체크가 4행이 아니거나 UNCHECKED 포함 | `확인` | 집계 제외 및 운영국 확인 안내 |

"결과 확정"의 출처는 날짜에 따라 둘 중 하나다.

- 2026-09-02 이후: 원장 status=SETTLED + 본인 체크 4행이 모두 PASS 또는 FAIL.
- 2026-08-24~09-01: 13.2 보관 테이블에 본인 4종 결과가 모두 있음.

상태 결정 순서 (위에서부터 처음 맞는 것을 쓴다):

1. 조회 범위(11.1) 밖이거나 재학 기간 밖(enrolled_at 이전, transferred_at 이후) → CLOSED. reason_code는 OUT_OF_RANGE 또는 NOT_ENROLLED.
2. 결과 확정 자료가 있음 → CLEAR 또는 PARTIAL. 휴업일인데 담임이 실제로 정산한 날이면 실제 운영일로 보고 기록을 표시한다. 단 토·일은 월~금 요약과 LIFE-002에서 제외한다.
3. 확정 원장(SETTLED)인데 본인 체크가 4행이 아니거나 UNCHECKED가 있음 → CHECK_NEEDED. 확인된 항목은 상세의 `확인된 기록`에 보여주되 분모에는 넣지 않는다.
4. 주말 또는 휴업일 → CLOSED. 그날 자동 생성된 미확정 원장(9/25 추석, 주말 DRAFT 등)은 무시한다.
5. 오늘 이후 → FUTURE.
6. 원장이 미확정이거나 오늘이면 → PENDING.
7. 그 밖의 지난 운영일(원장 없음) → CHECK_NEEDED.

상세 규칙:

1. 미정산 체크의 PASS/FAIL은 상세에서 표시할 경우 `임시 체크 · 확정 전` 구역에 분리한다. 기본 표와 달력에는 확정처럼 표시하지 않는다.
2. 오늘 정산이 끝나지 않았다고 기존 완료 기록을 0/4로 덮지 않는다. 로딩·오류·대기는 별도 상태다.
3. 지급 금액이 크거나 일급이 높다는 이유로 성공한 항목 수를 추정하지 않는다.
4. 퀘스트 보상 올클리어 행이 없더라도 유효한 4종 PASS를 실패로 만들지 않는다. 별도 보상 이벤트 누락과 체크 결과를 구분한다.
5. 모든 상태는 서버에서 정규화하고 날짜별 source/confidence/reason_codes를 함께 반환한다.
6. 정산 확정은 부모 report.status=SETTLED와 유효한 4종 PASS/FAIL로 판단한다. 개별 체크 settled_at은 PASS 보상 처리 시각이며 FAIL에는 정상적으로 null이다. `모든 체크 settled_at NOT NULL` 또는 `completion_id 존재`를 확정 조건으로 쓰지 않는다.
7. 원장 존재만으로 운영일이라고 판단하지 않는다. 운영일 여부는 13.1의 공통 판단 함수만 쓴다.
8. 미래 날짜에 SETTLED 원장이 있는 등 날짜 논리와 맞지 않으면 CHECK_NEEDED(reason_code DATA_CONFLICT)로 처리한다.

달력 칸 토큰은 `4/4`·`n/4`·`대기`·`미확정`·`예정`·`—`·`확인` 7가지뿐이다. 자세한 이름(예: `휴업일(추석)`, `기록 확인 필요`)은 범례/선택일 상세/접근성 이름에서 제공한다. 토큰은 4글자 이내, 추가 축소 없이 360px에서 확인한다.


## 8. 상단 요약과 분모

요약의 기간은 항상 선택한 주의 월~금이다. 연속 출석 카드만 현재 시점의 기존 공식 집계다.

| 카드 | 계산 | 예시 |
|---|---|---|
| 현재 연속 출석 | 기존 RPC current_streak·total_attendance | `12일째`, `누적 출석 인정 145일` |
| 선택 주 전체 완료 | CLEAR 일수 / 결과 확정 날짜 수(CLEAR+PARTIAL) | `3일 / 확정 4일` |
| 선택 주 퀘스트 | 결과 확정 날짜들의 PASS 수 / 해당 날짜의 기대 항목 수 | `15 / 16 완료` |

- 요약 카드의 큰 숫자는 `전체 완료 3일`로 읽히게 하고 분모는 보조 문구 `확정 4일 중`으로 둔다. 이를 주 5일 목표의 3/4 달성률처럼 보이게 하지 않는다.
- 현재 출석 카드에는 `현재`를 명시한다. 지난 달을 조회해도 현재 시점 출석 수치라는 것을 숨기지 않는다.
- 표 바로 아래 주간 분포를 항상 제공한다: 확정·미확정·예정·휴업·확인 필요 일수의 합이 월~금 5일이어야 한다. 전체 완료/미달은 확정일의 하위 분류이며 위 합계에 다시 더하지 않는다.
- 분포는 0이 아닌 항목만 작은 토큰으로 표시하고 자연스럽게 줄바꿈한다. 모바일 요약 카드에 3개 이상 긴 상태 문구를 nowrap으로 욱여넣지 않는다.
- 미확정 일수와 미래 예정 일수는 별도 표시한다. 모르는 날을 대기로 뭉뚱그리지 않는다.
- 기본 분모는 결과가 확정된 날짜에 한해 4개씩이다. 대기·예정·휴업·확인 필요 날짜는 완료율 분모에서 제외한다.
- 휴업일(주말·공휴일·학교 휴업일)은 모든 비율의 분모에서 뺀다. 앞으로 만들 전체 출석률·1인1역 완수율 등도 13.1의 공통 판단 함수로 같은 기준을 쓴다.
- 확정 0일이면 `확정 기록 없음`. `0/0`, 100%, 달성 가능 같은 표현을 쓰지 않는다.
- 한 주의 전체 완료 3일과 ‘업적 목표 5일’은 서로 다른 지표다. `3/4`를 업적 진행률로 사용하지 않는다.
- 선택한 주가 바뀌면 집계도 함께 바뀐다. 지난 달로 이동했는데 이번 주 수치를 남기지 않는다.

## 9. 주간 상세표와 선택일 상세

주간표에는 4종 행 + 전체 완료 행을 고정한다. 요일 머리는 요일/날짜 2줄이다. 정산 확정 여부와 항목별 결과는 7장의 상태를 따른다.

선택일 상세 영역에는 다음을 표시한다.

- 선택일과 실제 출결 상태: 예 `11.10 화요일 · 출석 인정`.
- 실패한 퀘스트가 있으면 모두 열거: `1인1역·청소 미완료`.
- 전부 성공한 날: `일일퀘스트 4개를 모두 완료했어요.`
- 미확정: `운영국 확정 전이에요. 이 화면의 확정 집계에는 아직 포함되지 않아요.`
- 휴업일: `휴업일이에요(추석).` / 주말: `주말이에요.` 주말 접속 출석이 있으면 `주말 접속 출석 ✓`를 함께 표시한다.
- 확인 필요(원장 없음·누락·모순): `기록 확인이 필요해요. 운영국에 문의해 주세요.`
- 조회 범위 밖: `2학기(8월 24일) 이전 기록은 이 창에서 볼 수 없어요.` / `2학기 기록은 1월 5일까지예요.`
- 8/24~9/1 기록: 상세 하단에 작은 글씨로 `2학기 첫 주 기록 · 이전 시스템에서 옮긴 자료`를 표시한다.

관리자 메모·반려 사유·다른 학생 정보는 원문으로 내려주지 않는다. 기본 사유는 FAIL인 항목명만으로 생성한다. 학생 공개가 확인되지 않은 교사용 메모를 노출하지 않는다.

## 10. LIFE-002 「퀘스트 마스터」 카드

### 10.1 기간 의미

현재 운영 기준은 같은 ISO 주의 월~금 5일이다. 휴일을 제외한 연속 5운영일이나 다른 주의 5일로 바꾸지 않는다. 휴업일이 있는 주를 4/4로 채웠다고 자동 충족으로 표시하지 않는다.

따라서 평일 휴업일이 낀 주(2026년 2학기: 9/21~25, 10/5~9, 12/21~25 등)는 현재 조건으로는 5일을 채울 수 없다. 카드에는 `휴업일이 있는 주예요 · 목표 5일 기록 미충족`으로 표시한다. 조건을 바꿀지는 별도 정책 결정이며 이 기능에서 바꾸지 않는다.

LIFE-002는 evaluation_type=QUALITATIVE, auto_eval_enabled=false로 교사가 검토해 승인한다. 이 카드는 학생의 신청 전 자기 확인과 교사 검토를 돕는 기록 안내다.

8/24~8/28 주는 13.2 보관 테이블로 표시하지만 기존 업적 검증 helper(v5)는 이 주를 읽지 못한다. 이 주를 선택하면 카드에 `2학기 첫 주는 이전 시스템 기록이에요. 업적 검증 도우미에는 나오지 않을 수 있어요.`를 표시한다.

선택 주에 대한 기록 안내와 이미 보유한 업적 상태는 분리한다. 학생이 과거 다른 주에 업적을 획득했으면 선택 주가 미달이어도 `보유 중`을 유지하며, 그 아래 `선택 주: 미달 기록 있음`으로 설명한다.

### 10.2 보유와 선택 주 판정은 독립 축

- 미공개: 서버에서 이름·조건·근거도 내려주지 않는다. 이름을 비우고 숨겨진 카드 높이를 예약하지 않는다.
- 공개 시 첫 배지는 현재 보유/미보유를 표시한다. 같은 학급·해당 업적의 is_revoked=false인 보유만 인정한다. 회수 이력을 보유 중으로 세지 않는다.
- 두 번째 영역은 선택 주의 기록만 설명한다. 보유 중이어도 현재 선택 주 기록은 별도로 표시한다.
- 확정이 유효한 날짜 중 FAIL이 하나라도 있으면 선택 주 결과는 `미달 기록 있음`이다. 다른 날짜가 불명확하다는 이유로 이 확정 실패를 숨기지 않는다.
- 월~금 5일 모두 유효하게 확정 4/4이면 `5일 전체 완료 기록`이다. 공식 승인·자동 신청·전 기간의 신청 가능 여부로 표시하지 않는다.
- 알려진 확정 FAIL이 없으나 CHECK_NEEDED 날짜가 있으면 `확인 필요`.
- 실패 없이 미래일이나 오늘 미정산이 남았으면 `진행 중 · 확정 후 확인`.
- 과거 미정산 원장이 남은 경우 `미확정 기록 있음`이며 이미 마감된 주를 진행 중이라고 부르지 않는다.
- 휴업일 또는 재학 기간 밖 날짜가 포함되어 5일을 확인하지 못하면 `목표 5일 기록 미충족`으로 이유(예: `휴업일이 있는 주예요`)를 표시한다.

조건 원문은 achievements.condition_text를 따른다. 보조 문구는 `이 카드는 선택한 주의 확정 기록을 보여줍니다. 업적 보유 여부는 별도로 표시합니다.`다.

### 10.3 현재 검증 함수와의 차이 — 이 화면의 한계

현재 v5 근거는 전체 주의 최대값을 구하며 report.status를 필터링하지 않는다. 새 화면의 선택 주 확정 기록과 직접 비교하면 기간과 확정 범위가 모두 달라져 거짓 불일치가 발생한다.

V1은 다음처럼 범위를 제한한다.

1. 카드에서는 선택 주의 확정 결과만 보여준다. 기존 검증 helper의 전 기간 최대 PASS/FAIL을 새 RPC가 호출하거나 그 값과 비교하지 않는다. 따라서 매달 조회 때 전체 이력을 스캔하지 않는다.
2. 공개 카드 하단에 `정산 전 체크를 포함하는 기존 검증 화면과 일시적으로 다르게 보일 수 있어요. 신청 전에는 확정된 기록을 확인해 주세요.`를 제공한다. 확정 대기일이 있으면 펼치지 않아도 이 안내를 확인할 수 있게 한다.
3. 신규 응답에 공식 eligible=true/false, 신청 가능/불가 같은 필드를 만들지 않는다. `record_summary_only` 범위를 명시한다.
4. 이미 보유한 업적과 선택 주 기록을 연결해 회수·변경하지 않는다. 과거 다른 주에서 달성했을 수 있다.
5. 현행 검증 함수에 SETTLED 필터를 넣거나 과거 승인 건을 재평가하는 일은 별도 정책·영향 검토다. 이 기능에서 수행하지 않는다.
6. 기존 LIFE-002 검증 자체에 항목 코드/중복/확정 상태 문제가 의심되어도 조회 화면을 위해 조용히 고치지 않는다. 대상 주의 기록 정합성은 이 기능의 4종 단위 검증으로 보수적으로 안내한다.
7. `신청 시점 당시 기록`과 `지금 저장되어 있는 과거 날짜의 기록`은 다를 수 있다. 이 창은 후자를 조회하는 기록 창이다. 별도 신청 시점 스냅샷을 복원하는 기능으로 설명하지 않는다.

## 11. 조회 범위와 2학기 첫 주 기록

### 11.1 조회 범위

- 조회 범위는 2026-08-24(월, 2학기 시작) ~ 2027-01-05(화, 학기 마지막 날)이다. 서버 한 곳(RPC 내부 상수 또는 공통 설정)에서만 정하고 프론트 여러 파일에 하드코딩하지 않는다.
- 월 이동은 2026년 8월 ~ min(현재 월, 2027년 1월)이다.
- 8/1~8/23과 1/6 이후 날짜는 CLOSED(OUT_OF_RANGE)이며 흐린 `—`로 둔다. 클릭할 수 없다.
- 1학기·여름방학 등 8/24 이전의 구버전 이력은 제공하지 않는다. 월 이동 하한에서 `2학기(8월 24일) 이전 기록은 이 창에서 볼 수 없어요.`를 안내한다.
- `school_terms` 값은 사용하지 않는다(실제 학기와 다름. 1장 참고).
- 다음 학기·다음 학년도 범위는 이 기능의 범위 밖이다. 필요할 때 상수 한 곳만 바꾸거나 별도 설정으로 옮긴다.

### 11.2 2026-08-24 ~ 09-01 (상세 원장 전환 이전)

- 이 기간에는 상세 원장(`daily_quest_reports`·`daily_quest_checks`)이 없다. 담임이 제공한 항목별 실패 명단을 13.2의 새 보관 테이블에 넣어 표시한다.
- 기존 원장에는 넣지 않는다. 넣으면 보상·정산 함수와 업적 검증 helper(v5)가 함께 읽는다.
- 보관 테이블은 이 기록 창의 조회에만 쓴다. 보상 재지급이나 업적 자동 판정에 쓰지 않는다.
- 이 기간에는 출결 원장(`attendances`)이 없다. 6장의 `출결 행이 없는 날의 표시` 규칙에 따라 보관 테이블의 `출석` 항목 결과로 달력 출석 표시를 정한다(일일퀘스트 기준이라고 명시). attendances에는 쓰지 않는다.
- 상세 원장 전환일은 2026-09-02다. 9/2 이후 날짜는 보관 테이블을 읽지 않는다. 8/31~9/4 주처럼 경계를 가로질러도 같은 날을 두 번 집계하지 않는다.
- `legacy_asset_history`의 보상 금액으로 항목별 결과를 추정하지 않는다. 금액은 담임 명단을 사후 대조하는 데만 썼다(13.2).
- 과거 조회를 위해 ensure_daily_quest_report나 teacher_create_daily_quest_report를 호출하지 않는다. 원장·지급 내역을 생성하지 않는다.

## 12. 서버 조회 계약 — 월 단위 읽기 전용 RPC

제안 공개 RPC: `student_get_my_attendance_quest_calendar(p_month date DEFAULT NULL)` → jsonb. 기존 함수와 이름·정확한 시그니처 충돌을 확인한 후 확정한다. 기존 student_get_attendance_dashboard는 다른 화면의 호환성을 유지한다.

### 12.1 요청과 조회 범위

- 공개 인자는 조회 월만 받는다. student_id/classroom_id/selected_date는 받지 않는다. 선택일 변경은 월 응답 안에서 즉시 처리하며 날짜 클릭마다 RPC를 호출하지 않는다.
- p_month=NULL은 서버 현재 월의 첫날이다. 초기 서버 날짜를 얻기 위한 별도 학생 데이터 조회를 만들지 않는다.
- 로그인 사용자·학생·학급을 내부에서 구하고 활성 역할/학급 일치를 검증한다.
- 월 시작은 서버에서 정규화한다. 조회 가능한 가장 이른 달과 현재 달 범위를 서버가 검증한다. 빈 기간을 무제한 이동할 수 없게 한다.
- 조회 범위는 11.1을 따른다(2026-08-24~2027-01-05). 범위 밖 월을 요청하면 가장 가까운 범위 안 월로 정규화하거나 명확한 오류 코드를 반환한다.
- 그 월의 모든 날짜와 월 경계에서 필요한 ISO 주 월~금의 합집합을 조회한다. 달력의 빈 앞뒤 칸에 기록을 표시할 필요는 없다. 일~토 그리드 범위를 함께 반환하더라도 최대 49일 이내다.
- 응답의 weeks[]는 해당 월 날짜가 속하는 모든 ISO 주의 월~금 5일을 포함한다. 날짜·요약·선택 주 카드 결과는 같은 응답 스냅샷에서 계산한다.
- 항목·보고서 조회는 학생/학급/날짜 범위로 제한한다. 임의 학생/학급을 인자로 지정할 수 없다.
- 현재 공식 연속출석·마일스톤·보상을 별도 재계산하지 않는다. 기존 공식 읽기 경로를 재사용할 때 root kst_today와 내부 조회의 기준일이 일치하는지 확인한다.

### 12.2 응답 필수 필드

| 필드 | 내용 |
|---|---|
| schema_version | 응답 버전 1 |
| kst_today / fetched_at | 한 번 확정한 서버 한국 날짜 / 조회 timestamp |
| month / range_start / range_end | 정규화한 월과 실제 반환 날짜 범위 |
| coverage | earliest_available_date(2026-08-24), latest_available_date(2027-01-05), latest_selectable_month, 상세 원장 전환일(2026-09-02) |
| attendance_summary | 현재 공식 연속출석·누적·마일스톤·오늘 출결 |
| days[] | 날짜별 출결/인정 여부, attendance_source, day_state, source, confidence, report_status, nullable pass_count, 기대 4종, 체크 결과, failure_codes, reason_codes, closure_kind, closure_label |
| weeks[] | week_start, week_end(금요일), 서로 겹치지 않는 날짜 상태별 일수, 확정 내 전체완료/미달 일수, PASS/기대 항목 합계, selected_week_record_status, warning_codes |
| achievement_catalog | 공개 여부, 공개 시 uid/name/condition, active_ownership, assessment_scope=record_summary_only |
| reward_summary | 기존 이번 달 출석/마일스톤 보상 및 명시적 reward_month |

정규화 값:

- day_state: CLEAR / PARTIAL / PENDING / FUTURE / CLOSED / CHECK_NEEDED (7장).
- source: DAILY_QUEST_CHECKS / LEGACY_TEACHER_RECORD(13.2 보관 테이블) / NONE. 출결 source는 attendance_source로 별도 취급한다(WEEKEND_APP_ACCESS 포함).
- confidence: VERIFIED(정합성 검증 완료) / UNCONFIRMED(미정산) / CONFLICT(모순).
- reason_codes 예: OUT_OF_RANGE, NOT_ENROLLED, WEEKEND, CLOSURE, NO_REPORT, MISSING_CHECKS, DATA_CONFLICT.
- closure_kind/closure_label: CLOSED가 휴업일 때문이면 13.1의 kind/label, 주말이면 WEEKEND/null.
- checks는 4종 키가 항상 존재하며 값은 PASS/FAIL/UNCHECKED/null이다. null은 원본 항목 부재이며 FAIL과 다르다.
- day_state가 PENDING/FUTURE/CLOSED/CHECK_NEEDED이면 pass_count=null이다. 원본 임시 체크가 PASS여도 확정 집계는 null이다.
- reason_codes는 서버가 정한 비기술적 상태 코드다. 교사 메모와 예외 SQL 원문을 포함하지 않는다.
- 응답은 공개하지 않은 업적 이름·조건·다른 학생 데이터를 포함하지 않는다. 헤더 캐시 계정 분리도 동일하게 적용한다.

날짜 객체 예시:

```json
{
  "date": "2026-11-10",
  "attendance_status": "PRESENT",
  "attendance_recognized": true,
  "day_state": "PARTIAL",
  "source": "DAILY_QUEST_CHECKS",
  "confidence": "VERIFIED",
  "report_status": "SETTLED",
  "pass_count": 3,
  "expected_count": 4,
  "checks": {
    "ATTENDANCE": "PASS",
    "PRIMARY_JOB": "FAIL",
    "LEARNING_MATERIALS": "PASS",
    "CLEANING": "PASS"
  },
  "failure_codes": ["PRIMARY_JOB"],
  "reason_codes": []
}
```

주간 분포 불변식: settled_days + unconfirmed_days + future_days + closed_days + check_needed_days = 5. complete_days + failed_days = settled_days. 합계가 다르면 UI에서 임의로 맞추지 않고 계약 오류로 처리한다.

### 보상 영역의 월 구분

기존 RPC의 보상은 현재 월 기준이다. 과거 달력을 보면서 그 값을 ‘선택 월 보상’으로 잘못 표시하면 안 된다. V1은 기존 공식 숫자를 유지하며 접이식 영역을 `이번 달 출석 보상(YYYY.MM)`으로 명시한다. 과거 월 보상을 지원할 경우 별도 서버 범위 조회를 구현한 후 `선택 월`로 바꾼다.

## 13. 신규 테이블·권한·정합성·성능

v1.2에서 신규 테이블은 아래 두 개만 만든다. 둘 다 조회 전용 자료이며 보상·정산 로직과 연결하지 않는다.

### 13.1 휴업일 테이블 `classroom_closures`

| 열 | 형식 | 설명 |
|---|---|---|
| id | bigint PK | |
| classroom_id | integer FK classrooms | 학급별 휴업일 |
| start_date / end_date | date | 하루면 같은 날짜. CHECK(end_date ≥ start_date) |
| kind | text CHECK | PUBLIC_HOLIDAY / SUBSTITUTE_HOLIDAY / SCHOOL_CLOSURE / VACATION |
| label | text | 학생에게 보이는 이름(예: `추석`) |
| created_at | timestamptz | |

- 주말은 넣지 않는다. 토·일은 규칙으로 계산한다.
- 공통 판단 함수 `_is_school_day(p_classroom_id integer, p_date date) returns boolean`: 주말이 아니고 휴업일 기간에도 포함되지 않으면 true. 내부 helper이며 학생 authenticated에 EXECUTE를 열지 않는다. 앞으로 전체 출석률·1인1역 완수율 계산에서도 이 함수를 쓴다.
- RLS를 켠다. 학생 직접 SELECT는 막고 기록 RPC(SECURITY DEFINER)를 통해서만 읽는다. 교사 접근은 기존 교사용 테이블의 정책 관례를 따른다.
- V1 입력 방법: 마이그레이션 시드. 교사 패널에서 등록·수정하는 화면(갑작스러운 임시공휴일 대비)은 다음 단계에서 만든다.
- 기존 출석 체크·일퀘 원장 자동 생성·보상 함수는 이 테이블을 읽지 않는다. 이번 기능에서 연결하지 않는다.

시드 (classroom_id=1, 조회 범위 안):

| 기간 | kind | label | 비고 |
|---|---|---|---|
| 2026-09-24 ~ 2026-09-25 | PUBLIC_HOLIDAY | 추석 | 담임 확인. 9/26은 토요일 |
| 2026-10-05 | SUBSTITUTE_HOLIDAY | 개천절 대체공휴일 | 담임 확인. 10/3은 토요일 |
| 2026-10-09 | PUBLIC_HOLIDAY | 한글날 | 담임 확인 |
| 2026-12-25 | PUBLIC_HOLIDAY | 성탄절 | 담임 확인 |
| 2027-01-01 | PUBLIC_HOLIDAY | 1월 1일 | 담임 확인 |

- 학교 자체 휴업일: 8/24 이후 없음(담임 확인).
- 시드 검증: 9/2~11/16 사이 실제 반에서 "원장 없는 평일"은 정확히 9/24, 10/5, 10/9뿐이었다(9/25는 자동 생성 DRAFT). 시드를 넣은 뒤 이 기간의 CHECK_NEEDED 날짜가 0개여야 한다.

### 13.2 2학기 첫 주 보관 테이블 `legacy_daily_quest_results`

| 열 | 형식 | 설명 |
|---|---|---|
| id | bigint PK | |
| classroom_id | integer FK classrooms | |
| student_id | integer FK students | |
| quest_date | date | CHECK(2026-08-24 ≤ quest_date ≤ 2026-09-01) |
| quest_code | text CHECK | ATTENDANCE / PRIMARY_JOB / LEARNING_MATERIALS / CLEANING |
| result | text CHECK | PASS / FAIL |
| source_note | text | 예: `담임 제공 명단 2026-11-17` |

- UNIQUE(student_id, quest_date, quest_code).
- RLS를 켠다. 학생 직접 SELECT는 막고 기록 RPC로만 읽는다.
- 대상 날짜는 8/24, 8/25, 8/26, 8/27, 8/28, 8/31, 9/1의 7일이다. 대상 학생은 실제 학생 24명(김나연 포함, 교사·테스트 계정 제외)이다. 7일 × 24명 × 4종 = 672행.
- 아래 명단에 없는 학생과 항목은 모두 PASS다.

| 날짜 | FAIL 항목 : 학생 |
|---|---|
| 8/24(월) | 1인1역: 김선율, 박서은, 이태우, 한동준 |
| 8/25(화) | 1인1역: 정민준, 한동준 |
| 8/26(수) | 1인1역+청소: 김윤우, 이예준, 이한성, 지담, 한서현 / 청소: 김나연, 김서영, 김선율, 김종현, 류은우, 이아정, 정우림, 한동준 |
| 8/27(목) | 청소: 김선율, 박시현, 우서윤, 이예준, 이하람, 이현석, 한동준, 이준혁 |
| 8/28(금) | 1인1역: 김나연, 김윤우, 부희주, 한동준 / 준비물: 한서현 (아래 참고) |
| 8/31(월) | 1인1역: 김나연, 김선율, 한동준 |
| 9/1(화) | 출석+준비물+1인1역: 김나연 / 1인1역: 김서영, 박시현, 김선율 |

- 명단의 이름 22개는 모두 `students`(classroom_id=1)의 이름과 정확히 일치함을 확인했다. 마이그레이션은 이름이 아니라 student_id로 넣고, 넣기 직전에 이름→id 매핑이 22명 모두 일치하는지 다시 확인한다.
- 보상 금액 대조(참고용, `legacy_asset_history`): 구버전 보상은 출석·준비물·청소 각 BV 100 + 1인1역 일급(100~150)으로 보인다. 8/24~8/31 명단의 실패 학생은 모두 금액과 맞았고, 4/4 학생 중 금액상 실패가 의심되는 경우도 없었다. 단 **8/28 한서현**은 처음 명단(1인1역 실패)과 금액(BV 350 = 450 − 100)이 맞지 않았다. 담임 확인 결과 1인1역·청소 실패가 아니며 출석 또는 준비물 중 하나인데 어느 쪽인지는 불명확하다. 담임 결정에 따라 **준비물(LEARNING_MATERIALS) 실패**로 넣고, source_note에 `담임 확인: 출석 또는 준비물 중 하나, 준비물로 표기`를 남긴다. 이에 따라 8/28 한서현의 출석 표시는 `출석 인정 (일일퀘스트 기준)`이 된다. 9/1은 보상 내역이 DB에 없어 대조하지 못했다.

### 13.3 권한·정합성·성능

- 신규 공개 RPC는 조회 전용. SECURITY DEFINER가 필요하면 고정 search_path, 활성 학생 및 학급 검증, 최소 반환 필드, 명시적 GRANT/REVOKE를 적용한다. anon/PUBLIC 실행은 차단한다.
- 내부 집계 helper는 학생 authenticated에 직접 EXECUTE를 열지 않는다. 학생에게 모든 체크 원장 SELECT 권한을 넓혀 해결하지 않는다.
- 상세 실패 사유는 본인 결과만 반환한다. 교사·다른 학급·다른 학생을 인자로 지정하는 우회 경로가 없어야 한다.
- 하루 체크의 중복은 UNIQUE 제약으로 생길 수 없다(2장). 그래도 본인 체크가 4행이 아니면 DISTINCT로 숨기지 않고 CHECK_NEEDED로 보고한다.
- 신규 테이블은 13.1·13.2의 두 개만 만든다. 필요 인덱스는 기존 pg_indexes 및 실행 계획을 확인한 후 증분으로 추가한다.
- 월 조회는 날짜마다 RPC를 호출하지 않고 집합 쿼리로 처리한다. 한 사용자의 한 달을 위해 전체 학급 전체 기간을 프론트로 가져오지 않는다.
- 단일 응답의 summaries와 days는 같은 조회 스냅샷에 기반해야 한다. 두 시점의 데이터가 섞여 3/4와 4/4가 동시에 보이지 않게 한다.
- 기록 창이 닫혀 있을 때는 신규 조회를 실행하지 않는다. 주/월 이동 요청 경합 시 현재 viewMonth와 계정에 일치하는 응답만 표시한다.
- query key에는 사용자·학생·학급 컨텍스트와 조회 월을 포함한다. 같은 월의 선택일/주는 key에서 제외한다. 날짜 선택만으로 요청하지 않으며 월 변경·명시적 재검증 이벤트 때 요청한다. 로그아웃·계정 변경 시 다른 학생 캐시가 노출되지 않게 초기화하고, 진행 중 요청을 취소하거나 이전 계정 key로만 귀속시킨다.
- 창 열기·포커스 복귀·명시적 새로고침 때 다시 확인한다. 기본 staleTime은 30초 내외. 별도 고빈도 polling과 학생마다 테이블 직접 Realtime 구독은 추가하지 않는다.
- 같은 월의 캐시 재검증 중에는 기존 내용을 유지하고 조회 시각/갱신 중을 표시한다. 다른 월로 이동했는데 그 월 캐시가 없다면 안정된 높이의 skeleton을 사용한다. 이전 월의 4/4를 새 월 날짜 밑에 그대로 놓지 않는다. 이전 월 응답은 그 월 key에만 저장한다.
- `enabled = isOpen && authenticated && studentContextReady`를 적용한다. 30초 staleTime이라도 다시 열기·포커스 복귀·수동 새로고침에는 서버 재검증을 수행한다. 실제 React Query 설정에서 refetchOnMount/refetchOnWindowFocus의 always 동작을 명시한다. 모바일 복귀는 visibilitychange가 필요한지 점검하고 같은 이벤트 요청을 dedupe한다.
- 화면에 현재 조회 시각과 새로고침 조작을 제공한다. 실패 후 버튼 재시도 시 재무 쓰기 RPC를 호출하지 않는다.

## 14. 로딩·오류·접근성

- 첫 로딩: 카드·달력·표의 실제 높이를 유지하는 skeleton. 0일/0/4를 임시 데이터로 표시하지 않는다.
- 조회 실패: 현재 기간과 재시도 버튼, 학생 친화적 오류. 데이터 없음과 서버 오류는 구분한다.
- 이전 데이터가 있다면 ‘이전 조회 기록 · 갱신 실패’를 표시하고 업적 충족을 새 확정 결과처럼 안내하지 않는다.
- 월/주 이동 시 스크롤 위치와 포커스를 과도하게 초기화하지 않는다. 모바일 날짜 선택 자체로 자동 스크롤하지 않는다. 5.3장의 명시적 이동 버튼만 사용한다.
- 날짜 버튼의 접근성 이름 예: `11월 10일 화요일, 출석 인정, 일일퀘스트 4개 중 3개 완료`.
- 표는 table/thead/tbody/th(scope=row 또는 col)을 사용한다. 체크/미달 기호에 완료/실패 대체 이름을 제공한다.
- 키보드 Tab/Enter, 보이는 포커스, ESC 닫기, 모달 focus trap, 닫은 후 홈 버튼 포커스 복귀를 확인한다.
- 200% 글자 확대에서 컨텐츠가 잘리지 않고 세로 스크롤로 접근 가능해야 한다. 가로 표가 불가피하게 넘치는 매우 큰 글자 설정에서는 접근성을 우선하고 일반 배율의 360px 무가로스크롤 기준과 구분한다.
- 전환은 짧은 opacity 중심으로 처리하고 갑자기 화면을 비웠다 채우지 않는다. reduced-motion을 존중한다.

## 17. 완료 정의

- 화면은 승인된 시안의 구조와 밀도를 유지한다.
- 학생은 달력 또는 주간표에서 날짜를 선택하여 그날의 미달 항목과 해당 주 전체 상태를 확인할 수 있다.
- 출석 인정과 퀘스트 완료, 확정과 대기, 휴업과 확인 필요를 혼동하지 않는다.
- LIFE-002 카드가 보유 상태·선택 주 기록·공식 승인 여부를 혼동시키지 않는다.
- 과거 기록을 추정으로 채우거나 재지급하지 않는다.
- 권한/무쓰기/기간 경계/표 레이아웃 테스트가 통과한다.
- 사용자 로컬 build와 실제 학생 화면 확인 결과를 기록한다. 수행하지 못한 검증은 완료로 보고하지 않는다.
