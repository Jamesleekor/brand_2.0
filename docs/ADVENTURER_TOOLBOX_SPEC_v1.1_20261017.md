## 1 문서 목적과 적용 범위

B.R.A.N.D 안에 수업과 학급 운영에 필요한 도구를 모은 **모험가 도구함**을 만든다. 교사는 기존 학생 명단과 길드를 클릭하거나 터치해 참가자를 구성하고, 추첨·게임·투표·발표 활동을 진행한다. 학생은 교사가 연 활동에 자신의 계정으로 참여하며, 추첨·순서·타이머·팀 만들기 같은 개인 도구는 학교생활 중 스스로 꺼내 쓴다.

본 문서는 사용자가 경험할 기능, 화면 동작, 운영 규칙, 예외 처리 및 완료 기준을 정의한다. 코드 작성 방식, 파일 구조, 데이터베이스 구조, 통신 방식, 라이브러리 등 구체적인 기술 구현 방법은 구현 담당자가 정한다. 다만 v1.1에서는 2026년 10월 17일 기준 GitHub main 저장소와 운영 Supabase의 구조를 읽기 전용으로 확인했으며, 그 결과 중 기능에 영향을 주는 사실을 부록 A에 정리했다. 실제 학생 데이터는 조사하지 않았다.

### 1.1 요구사항의 구분

- **합의한 필수 범위:** 아래 11개 도구, 공통 명단 선택, 직접 입력, 제외·중복 설정, 투표·점수 기록, 전체 화면, 연출·소리 조절, 명단 재사용 및 도구 간 연결이다.
- **이 문서의 운영 기본값:** 사용 흐름을 완성하기 위해 구체화한 초기 설정과 예외 규칙이다. 별도 표시가 없어도 이번 버전의 구현 기준으로 적용하되, 학생·교사가 바꿀 수 있다고 명시된 항목은 설정을 제공한다.
- **후속 검토 범위:** 외부 손님 입장 코드, 재화 자동 지급 등 13.2절의 항목이다. 이번 버전 필수 기능에 포함하지 않는다.

- **학급 활동(5종):** 교사만 만들고 진행한다. 학생은 참여(버저·투표·카드 구름)하거나 시청(대진표·점수판)한다.

## 3 접근 권한과 기본 화면

### 3.1 교사

교사 운영 패널에서 모험가 도구함에 진입할 수 있어야 한다. 메뉴 위치의 운영 기본값은 '길드 & 콘텐츠' 그룹의 '이벤트' 다음이며 교사가 다른 위치를 지정하면 그에 따른다. 첫 화면에는 11개 도구와 각 도구의 짧은 설명, 진행 중 학급 활동, 투표·점수 기록을 표시한다. 교사는 도구 설정, 참가자 선정, 활동 시작·중지·종료, 결과 공개, 기록 조회·삭제를 수행한다.

교사 운영 화면과 학생에게 보여 줄 발표용 화면을 구분한다. 전체 화면에서는 교실 뒤에서도 핵심 내용이 읽혀야 하며, 명단 선택 패널이나 비공개 설정이 학생에게 불필요하게 노출되지 않아야 한다. 전체 화면 진입·해제 자체로 진행 상태가 바뀌지 않는다.

### 3.2 학생

학생 홈 상단 메뉴 줄에 **'모험가 도구함'** 버튼을 추가한다. 위치는 '과제'와 '기록실' 사이, 즉 **'기록실' 바로 왼쪽**이다. 데스크톱 화면에서 메뉴 줄이 두 줄로 넘어갈 때도 '기록실' 왼쪽에 붙어 있어야 하며, 휴대전화·태블릿 폭에서도 버튼 이름이 잘리지 않아야 한다. 아이콘과 문구는 기존 메뉴 버튼과 같은 형식을 따른다.

도구함 첫 화면은 두 영역으로 나눈다.

- **나의 도구:** 제비뽑기·사다리타기·룰렛·순서 정하기·타이머·스톱워치·팀 만들기. 언제든 혼자 쓸 수 있다(3.5절).
- **지금 열린 학급 활동:** 버저·투표·발표 카드 구름 중 자신이 참가할 수 있는 활동과, 공유된 점수판·대진표. 학생은 활동 제목·종류·참여 상태를 확인하고 입장한다. 열린 활동이 없으면 이 영역은 빈 상태 안내만 보여준다.

학급 활동이 새로 열려 있으면 '모험가 도구함' 버튼에 표시(배지)를 붙여 학생이 알 수 있게 한다. 이 표시를 위해 홈 화면이 계속 서버를 조회해서는 안 되며 15.1절 기준을 따른다.

학생은 자신의 응답·제출만 수행할 수 있다. 교사의 진행 조작, 다른 학생 응답 수정, 공개 전 결과 열람은 할 수 없다. 학생의 참여 가능 여부는 로그인한 실제 계정과 활동 참가 자격을 기준으로 판단한다.

학생에게 보이는 문구에서는 B.R.A.N.D 세계관 규칙에 따라 '선생님' 대신 **'운영국'**을 행위 주체로 쓴다. 예: "운영국이 투표를 열면 참여할 수 있어요."

### 3.3 활동 생성 및 상태

기본 흐름은 **도구 선택 → 설정 및 참가자 구성 → 시작 → 진행 → 종료 → 기록 확인**이다. 준비 중, 참여 대기, 진행 중, 일시 중지, 종료 등 해당 도구에서 필요한 상태를 명확히 표시한다. 모든 도구에 불필요한 상태를 억지로 적용하지 않는다.

도구별 활동 제목을 수정할 수 있으며 기본 제목에는 도구 이름과 생성 시각을 사용한다. 학생이 참여하는 활동은 교사가 참여를 열기 전에는 학생 홈에 나타나지 않는다. 진행 중 교사 화면을 나갔다가 돌아오더라도 활동을 이어갈 수 있다.

### 3.4 학급 활동의 세 화면

선착순 버저·팀 점수판·토너먼트 대진표·투표·발표 카드 구름은 같은 활동을 세 화면으로 나누어 보여준다. 기존 경매·레이드의 운영 화면과 중계 화면 분리 방식을 따른다.

| 도구 | 교사 설정·운영 화면 | 교사 중계 화면(교실 대형 화면) | 학생 화면 |
| --- | --- | --- | --- |
| 팀 점수판 | 팀 등록·점수 조작·취소·초기화 | 팀별 점수와 순위를 크게 표시 | 팀별 점수판 읽기 전용 |
| 토너먼트 대진표 | 참가자·대진 설정·승자 선택·정정 | 대진표 생성 연출, 경기 진행, 우승 연출 | 대진표 생성 연출과 결과 읽기 전용 |
| 투표 | 투표 만들기·열기·마감·결과 공개·학생별 선택 확인 | 참여 수, 공개된 결과 | 자기 투표 제출·수정, 공개된 결과 보기 |
| 발표 카드 구름 | 활동 설정·제출 관리·숨김·발표 완료 표시 | 카드 구름, 선택한 카드 펼치기 | 제목·내용 입력과 수정 |
| 선착순 버저 | 라운드·배점·판정 조작 | 접수 순서, 정답 표시 | 버저 버튼, 자기 상태(대기·LOCK·접수됨) |

- 중계 화면은 교사 계정으로만 열며, 교사 운영 화면에서 새 창이나 전체 화면으로 띄운다.
- 중계 화면에는 학생별 투표 선택, 숨긴 카드, 작성자 숨김 상태의 이름, 운영 메모를 절대 표시하지 않는다.
- 학생 화면에서 보는 점수판·대진표는 교사가 '학생에게 공유'를 켠 경우에만 나타난다. 기본값은 활동 시작 시 공유 켜짐이다.
- 대진표 생성 연출은 중계 화면과 학생 화면이 같은 결과를 보여주어야 한다. 연출 도중 화면에 들어온 학생은 결과가 바로 보이거나 남은 연출부터 이어 보며, 다른 결과를 보는 일은 없어야 한다.

### 3.5 개인 도구

제비뽑기·사다리타기·룰렛·순서 정하기·타이머·스톱워치·팀 만들기는 학생과 교사 누구나 혼자 쓰는 개인 도구다.

- 개인 도구는 **서버에 결과를 저장하지 않으며 다른 사람에게 전송되지 않는다.** 결과는 사용한 기기 화면에서만 보인다.
- 같은 기기에서 새로고침했을 때 진행 중인 결과(공개된 제비, 남은 타이머 시간 등)를 이어 보도록 그 기기 안에만 잠시 보관할 수 있다. 보관에 실패해도 도구는 정상 작동해야 한다.
- 학생이 개인 도구에서 학급 명단·길드를 불러와 쓸 수 있다(4.1절). 명단 저장 기능은 교사에게만 제공한다.
- 개인 도구의 결과는 학생 자산·업적·길드 점수 등 어떤 공식 기록에도 반영되지 않는다. 화면에 "연습·놀이용 결과이며 기록되지 않아요" 수준의 안내를 둔다.
- 교사가 수업 중 개인 도구를 발표용 전체 화면으로 쓰는 것을 지원한다. 이때도 기록은 남기지 않는다.
- 6장·8장·12.1절의 '활동 시작·회차·재접속' 관련 규칙은 개인 도구에서는 같은 기기·같은 화면 안의 동작으로 해석한다.

## 4 공통 참가자 선택 패널

### 4.1 적용 도구

제비뽑기, 사다리타기, 룰렛, 순서 정하기, 선착순 버저, 토너먼트 대진표, 팀 점수판, 팀 만들기에는 동일한 사용 방식의 참가자 선택 패널을 필수 제공한다. 투표와 발표 카드 구름의 참여 대상 선정에서도 같은 학생 선택 경험을 재사용한다.

개인 도구 6종에서는 학생도 같은 패널로 자기 학급 학생·길드를 불러오거나 직접 입력할 수 있다. 학생용 패널에는 명단 저장(4.6절)과 출석 자동 제외(4.2절)를 제공하지 않는다. 학생은 필요 없는 이름을 직접 선택 해제한다.

### 4.2 학생 선택

- 기존 B.R.A.N.D의 해당 학급 학생을 이름 버튼으로 표시한다. 명단을 다시 입력하거나 별도로 관리할 필요가 없어야 한다.
- 표시 대상은 해당 학급의 현재 재학 학생이다. 전출 처리된 학생, 테스트 계정, 학생이 아닌 계정은 표시하지 않는다.
- 교사 화면의 이름 버튼은 본명을 기본으로 표시한다. 학생 화면과 중계 화면은 기존 B.R.A.N.D 학생 화면의 이름 표시 규칙을 따른다. 어느 화면이든 동명이인은 브랜드명(닉네임)을 함께 표시해 구분한다.
- 이름을 클릭·터치하면 선택되며, 선택 여부를 색상과 표시로 구분한다.
- 전체 선택, 전체 해제, 이름 검색을 제공한다.
- 선택한 학생 수와 최종 참가자 수를 즉시 표시한다.
- 결석·미참여 학생은 이번 활동에서만 제외할 수 있다. 기존 학생 계정이나 학급 명단은 변경하지 않는다.

**오늘 출석 연동(교사 패널):** 교사 운영 패널 '학생 관리 → 출석·과제 운영(F4C · 4.1)'에 기록된 오늘 출석을 참조한다.

| 오늘 출석 상태 | 참가자 선택 패널의 기본 처리 |
| --- | --- |
| 출석 | 포함 |
| 지각 | 포함 (교실에 있는 것으로 봄) |
| 인정결석 | 포함 (교실에 있는 것으로 봄) |
| 결석 | **자동 제외** |
| 오늘 기록 없음 | 포함 |

- 오늘 출석을 아직 입력하지 않았다면 전원을 포함하고 "오늘 출석 기록이 아직 없어요" 안내를 보여준다.
- 자동 제외된 학생은 '결석으로 제외됨' 표시와 함께 패널에 남아 있으며, 교사가 한 번 눌러 다시 포함할 수 있다.
- 도구함은 출석 기록을 읽기만 한다. 출석을 입력·수정하는 곳은 기존 출석·과제 운영 화면이다.
- 활동을 시작한 뒤 출석 기록이 바뀌어도 이미 고정된 참가자 명단은 자동으로 바뀌지 않는다(4.6절).

### 4.3 길드 선택

기존에 존재하는 길드를 이름과 식별 가능한 표식으로 표시한다. 실제 등록된 정보가 기준이며 특정 길드명이나 구성원을 문서의 예시로 고정하지 않는다. 표시 대상은 해당 학급의 활성 길드이며, 구성원은 현재 활성 소속 학생이다(탈퇴·이동한 과거 소속은 제외).

기존 길드 정보에는 고유 색상이 없다. 길드나 팀에 색상이 필요한 도구(점수판·대진표·팀 만들기)는 도구함 안에서 색상을 정한다. 기본값은 정해진 팔레트에서 겹치지 않게 자동 배정하고 교사가 바꿀 수 있게 하는 것이다. 이 색상은 해당 활동 안에서만 쓰며 길드 정보 자체를 바꾸지 않는다. 길드 로고가 등록되어 있으면 표식으로 함께 쓸 수 있다.

길드 추가 전 다음 두 방식을 명확히 선택한다.

| 추가 방식 | 동작 | 예시 |
| --- | --- | --- |
| 길드를 참가 단위로 추가 | 길드 하나를 참가자 한 항목으로 등록 | 길드 5개로 룰렛·대진표·점수판 구성 |
| 길드 구성원을 개별 추가 | 해당 길드 학생들을 각각 참가자로 등록 | 길드원 4명을 개인 발표 순서에 추가 |

길드 구성원을 개별 추가한 경우 일부 학생만 제외할 수 있다. 여러 길드의 구성원을 추가하거나 학생 직접 선택과 섞어도 같은 학생은 한 번만 들어간다. 구성원이 없는 길드는 개별 추가가 불가능한 이유를 표시한다. 길드를 참가 단위로 추가하는 것은 빈 길드라도 허용하되 버저 참여자는 별도로 확인해야 한다.

### 4.4 직접 입력

- 이름·닉네임·임의 팀명·추첨 항목을 한 개씩 추가할 수 있다.
- 여러 항목을 줄바꿈 또는 쉼표로 구분해 한꺼번에 추가할 수 있다.
- 앞뒤 공백과 빈 항목은 제거하고, 실제로 추가될 항목을 확인할 수 있게 한다.
- 직접 입력한 이름이 기존 학생과 같아도 학생 계정에 자동 연결하지 않는다. 중복 가능성을 알려 기존 학생을 선택하거나 별도 항목으로 유지하게 한다.
- 동일한 자유 입력 이름을 여러 개 넣으려면 별개 항목임을 확인하고 구분 표시를 붙인다. 결과 제비처럼 같은 문구의 반복이 필요한 경우에는 개수를 설정해 등록할 수 있다.

### 4.5 선택 명단 관리

선택 목록에는 학생·길드·직접 입력 항목의 종류를 구분해 표시한다. 항목별 제거, 표시 순서 조정, 전체 해제를 제공한다. 동명이인이나 같은 닉네임은 식별 표식으로 구분하며 결과 화면에도 그 구분을 유지한다.

학생과 길드가 혼합된 경우 실행 전에 참가 단위가 섞였다는 사실과 최종 명단을 보여준다. 혼합 사용을 일괄 금지하지 않되, 버저처럼 실제 계정 연결이 필요한 도구에서는 연결이 끝나야 시작할 수 있다.

학생 중복 여부는 이름이 아닌 동일 학생인지에 따라 판단한다. 같은 길드를 여러 번 선택해도 중복 등록하지 않는다. 직접 입력 항목은 기존 학생·길드와 임의로 합치지 않는다.

### 4.6 명단 재사용 및 고정

- 최근 사용한 명단을 불러오고, 저장한 명단을 다시 사용할 수 있다.
- 명단에는 이름을 붙일 수 있다. 저장·수정·삭제는 교사만 수행한다.
- 학생 계정이 더 이상 선택 가능한 상태가 아니면 불러올 때 알리고 제외 여부를 정한다.
- 길드 명단을 재사용할 때 현재 길드 구성원을 사용할지, 당시 구성원을 사용할지 구분해 선택한다. 현재 정보와 달라진 부분은 확인할 수 있어야 한다.
- 활동이 시작되면 참가자와 구성원을 고정한다. 중간에 명단을 바꾸려면 준비 단계로 돌아가며, 기존 결과를 유지할 수 없는 경우 어떤 결과가 초기화되는지 먼저 알린다.
- 과거 기록(투표·점수판, 14절)은 당시 이름·길드·구성원 기준으로 보존한다. 이후 실제 길드 이동이나 이름 변경이 과거 기록을 바꾸지 않는다.
- 저장 명단과 최근 명단은 교사 운영 패널에만 있다. 학생 개인 도구는 명단을 서버에 저장하지 않는다.

## 5 공통 진행과 결과 규칙

### 5.1 추첨 공정성과 결과 연출

제비뽑기·사다리타기·룰렛·순서 정하기·팀 만들기·대진 무작위 배정은 동일 자격의 항목에 동일한 기회를 부여한다. 이번 버전에는 가중 확률 설정을 넣지 않는다. 같은 문구가 여러 개 있는 제비는 문구가 아닌 제비 한 개를 같은 확률의 단위로 본다.

추첨 결과와 실제 화면 연출은 일치해야 한다. 연출을 건너뛰거나 소리를 끄거나 화면을 새로 열어도 이미 정해진 결과가 바뀌지 않는다. 재실행은 새로운 회차로 기록하며 기존 결과를 조용히 덮어쓰지 않는다.

반복 선택 도구는 중복 당첨 허용 여부와 당첨 항목 자동 제외 여부를 명확히 보여준다. 기본값은 같은 활동 내 중복 당첨 방지이며, 남은 항목이 없으면 다음 추첨을 막고 명단 복원 또는 새 회차 시작을 안내한다. 전원 순서·팀 편성·대진 배정에는 중복 당첨 설정을 적용하지 않는다.

### 5.2 전체 화면과 입력

교사 화면은 마우스와 터치로 사용할 수 있어야 한다. 작은 버튼이나 드래그만으로 가능한 필수 조작을 피한다. 발표용 전체 화면에는 결과·카드·시간·점수 등 핵심 내용을 크게 표시한다. 긴 이름과 많은 참가자로 인해 내용이 잘리거나 항목이 선택 불가능해지지 않아야 한다.

### 5.3 연출과 소리

추첨 도구는 일반 연출과 빠른 결과 보기를 제공한다. 소리가 있는 도구에는 소리 켜기·끄기를 제공하며 설정을 유지한다. 결과를 장시간 가리는 과한 연출을 피한다. 카드 구름 등 움직임이 있는 화면은 움직임을 줄일 수 있어야 한다.

### 5.4 저장과 복구

저장 범위는 도구 성격에 따라 다르다.

| 구분 | 활동 중 저장 | 활동 종료 후 |
| --- | --- | --- |
| 개인 도구 6종 | 서버 저장 없음. 같은 기기 안에서만 잠시 보관 가능(3.5절) | 보관하지 않음 |
| 선착순 버저·토너먼트 대진표·발표 카드 구름 | 학생 참여·시청을 위해 진행 상태를 서버에 저장 | **보관하지 않음.** 버저로 반영한 점수는 점수판 기록에 남음 |
| 팀 점수판 | 서버에 저장 | 기록으로 보관(14절) |
| 투표 | 서버에 저장 | 기록으로 보관(14절) |

- 보관하지 않는 활동을 종료할 때는 "종료하면 이 활동의 내용은 남지 않아요"를 확인받는다. 종료 전까지는 언제든 다시 열어 이어 갈 수 있다.
- 종료 처리된 활동의 내용(버저 순서, 대진 결과, 카드 원문)은 학생·중계 화면에서도 사라진다.
- 교사가 종료하지 않고 방치한 학급 활동은 일정 기간(운영 기본값 7일) 뒤 자동 종료·정리한다. 자동 정리 대상은 투표·점수판을 제외한 학급 활동이다.

활동 설정, 참가자, 진행 상태, 확정 결과, 기록 저장 여부를 교사가 확인할 수 있어야 한다. 학급 활동은 새로고침이나 재접속 시 마지막 저장된 상태로 돌아온다. 연결이 끊겨 반영 여부를 알 수 없는 경우 완료된 것처럼 표시하지 않는다. 재접속이나 재시도 때문에 표·카드·점수·버저 입력이 중복 반영되어서는 안 된다.

삭제·전체 초기화·완료 결과를 바꾸는 재추첨은 영향 범위를 알리고 확인한다. 점수 변경·승자 오선택·카드 발표 완료 표시 등은 취소할 수 있어야 한다. 실제 학생의 버저 순서나 투표를 교사가 원하는 내용으로 바꾸는 기능은 제공하지 않는다.

## 6 추첨 및 순서 도구 상세

### 6.1 제비뽑기

**설정:** 참가자, 결과 문구와 문구별 제비 수, 공개 방식, 연출·소리.

사용자는 결과 목록을 만들고 같은 외형의 가려진 제비들을 섞는다. 결과 문구는 공개 전 화면에 보이지 않아야 한다. 기본 동작은 사용자(학생 또는 교사)가 참가자를 선택한 뒤 제비를 터치해 그 참가자의 결과를 공개하는 방식이다. 제비뽑기는 개인 도구이므로, 한 사람이 만든 제비를 여러 학생이 각자 기기에서 나눠 뽑는 공유 기능은 이번 버전에 포함하지 않는다.

참가자별 배정 모드에서는 제비 수가 참가자 수와 같아야 한다. 인원이 맞지 않으면 부족·초과 수를 안내하고 시작을 막는다. 참가자 없이 제비만 뽑는 모드도 제공한다. 선택한 제비는 다시 고를 수 없으며 선택자·결과·남은 제비 수를 표시한다. 한 개씩 공개와 남은 제비 전체 공개를 지원한다.

**완료 기준:** 24명에게 당첨 3개·비당첨 21개를 중복 없이 배정할 수 있고, 다시 접속해도 공개된 결과가 유지된다.

### 6.2 사다리타기

**설정:** 참가자 목록, 동일 개수의 결과 항목, 연출·소리.

상단 참가자와 하단 결과를 같은 수로 구성한다. 결과 문구가 같아도 서로 다른 결과 칸으로 취급한다. 시작 전 사다리를 다시 만들 수 있고 시작 후에는 연결 관계를 고정한다. 참가자를 선택하면 경로를 따라가며 결과를 공개한다. 전체 결과 공개도 가능하다.

표시된 사다리 경로와 최종 결과가 일치해야 하며 각 출발점은 서로 다른 도착점에 연결되어야 한다. 참가자가 많으면 가로 이동이나 확대·축소 등을 통해 이름·경로·결과를 확인할 수 있어야 한다.

**완료 기준:** 24명의 경로를 모두 확인했을 때 도착점이 중복되지 않고 화면의 경로와 기록된 결과가 일치한다.

### 6.3 룰렛

**설정:** 학생·길드·자유 입력 항목, 중복 당첨 허용 여부, 당첨 항목 자동 제외, 연출·소리.

동일 확률의 영역으로 항목을 표시한다. 항목이 많아 이름이 원판에 모두 들어가지 않아도 별도 목록과 당첨 결과로 참가 대상을 식별할 수 있어야 한다. 회전 중 중복 실행을 막고 멈춘 위치와 결과를 일치시킨다. 당첨 이력과 남은 대상 수를 표시한다.

자동 제외가 켜져 있으면 다음 회차에서 당첨 항목을 제외한다. 중복 허용을 켜면 자동 제외는 끄는 등 서로 충돌하는 설정을 동시에 적용하지 않는다. 교사가 제외 목록을 확인하고 전체 복원할 수 있다.

**완료 기준:** 학생 24명을 중복 없이 한 명씩 뽑으면 24회 후 모두 한 번씩 당첨되고 25번째 실행은 안내와 함께 제한된다.

### 6.4 순서 정하기

선택한 모든 참가자에게 1번부터 마지막 번호까지 중복 없이 순서를 배정한다. 전체 한 번에 공개와 한 명씩 공개를 지원하며 전체 순서가 확정된 뒤 공개 방식에 따라 결과가 달라지지 않는다. 발표한 참가자를 완료 표시하고 다음 참가자를 강조할 수 있다.

전체 다시 섞기는 기존 회차를 남긴 뒤 새 회차로 진행한다. 이미 발표한 사람을 제외하고 남은 순서만 다시 섞는 기능은 별도 동작으로 구분하고 완료된 참가자 순서는 보존한다.

발표 타이머를 연결해 쓸 수 있다(8.3절). 연결하면 '다음 사람' 동작 한 번으로 현재 참가자 완료 표시, 다음 참가자 강조, 타이머 다시 시작이 함께 일어난다.

**완료 기준:** 길드 구성원과 개별 학생을 섞어 추가해도 동일 학생은 한 번만 포함되며 최종 인원만큼 순번이 생성된다.

## 7 선착순 버저

### 7.1 참가 방식

개인전과 팀전을 제공한다. 개인전은 선택한 학생 계정이 각각 자기 이름으로 참여한다. 팀전은 길드 또는 만들어진 팀을 참가 단위로 사용하고, 팀 대표 1명만 누르기 또는 구성원 누구나 누르기 중 선택한다. 대표자 모드에서는 팀별 대표 지정을 마쳐야 시작할 수 있다.

길드를 참가 단위로 추가하면 현재 구성원을 확인하고 활동 시작 시 참여 명단을 고정한다. 직접 입력한 참가자·팀도 표시할 수 있으나 실제 학생 계정을 연결해야 버튼 입력이 가능하다. 연결되지 않은 이름만으로 학생 참여가 가능하다고 표시하지 않는다. 외부 비로그인 참가자는 이번 버전 대상이 아니다.

### 7.2 진행

1. 교사가 활동을 열면 학생이 입장하고 교사는 참가 준비 상태를 확인한다.
2. 교사가 이번 문제의 배점을 정한다(7.3절).
3. 라운드를 열기 전에는 학생 화면에 '대기 중'을 표시한다. 버튼은 보이지만 이때 누르면 **부정출발**로 처리한다(아래 규칙).
4. 라운드를 열면 버튼이 활성화되며 입력 접수 순서를 표시한다.
5. 교사는 정답·오답 또는 별도 판정 없이 라운드 종료를 선택한다.
6. 다음 라운드를 열면 이전 입력 잠금을 해제하고 새 순서를 받는다.

**부정출발 5초 LOCK**

- 라운드가 열리기 전에 버저를 누르면 그 학생(팀전에서는 누른 학생 본인)의 버저가 **5초 동안 잠긴다.**
- 학생 화면에는 'LOCK'과 남은 초를 크게 표시한다. 잠긴 동안 누르는 입력은 무시하며 잠금 시간을 늘리지 않는다.
- 잠금 중에 라운드가 열려도 5초가 지날 때까지는 누를 수 없다. 5초가 지나면 그 라운드에 정상적으로 참여할 수 있다.
- 부정출발 여부와 잠금 시간의 기준은 학생 기기가 아니라 시스템이 입력을 받은 시점이다. 학생 기기 시계를 조작해도 결과가 바뀌지 않아야 한다.
- 교사 운영 화면에는 이번 라운드의 부정출발 학생을 표시한다. 중계 화면 표시 여부는 교사가 정하며 기본값은 표시하지 않음이다.
- 부정출발은 점수를 깎지 않는다.

라운드당 개인 또는 팀의 첫 입력만 유효하다. 구성원 누구나 누르기 모드에서도 같은 팀의 추가 입력은 순위에 추가되지 않는다. 교사에게 팀명과 실제로 누른 학생을 함께 표시한다.

기본값은 모든 유효 참가자의 순서를 받는 방식이다. 첫 입력만 받고 즉시 닫는 모드도 제공한다. 순위는 시스템에 유효하게 접수된 순서임을 안내하며 네트워크 지연이 있는 환경에서 실제 손가락을 누른 시각을 완벽하게 비교한다고 설명하지 않는다. 입력 수신 전 학생 화면에서 확정 순위를 미리 표시하지 않는다.

오답 시 자동으로 다음 순위를 우승자로 바꾸거나 점수를 지급하지 않는다. 교사가 다음 순위에 답변 기회를 주거나 새 라운드를 여는 방식으로 진행한다. 라운드별 순서와 판정은 활동이 끝날 때까지 교사 화면에서 확인할 수 있으며, 활동 종료 후에는 보관하지 않는다(5.4절). 점수판에 반영한 점수는 점수판 기록에 남는다.

### 7.3 문제별 배점과 점수판 연결

버저 활동에 팀 점수판을 연결할 수 있다. 연결하면 버저의 참가 단위(개인 또는 팀)가 점수판 항목과 같아야 한다. 팀 만들기 결과나 길드로 버저를 만들면 같은 구성으로 점수판을 함께 만들 수 있다.

- 라운드를 열기 전에 **이번 문제의 배점**을 입력한다. 숫자 직접 입력과 자주 쓰는 배점 빠른 버튼(예: 5·10·50·100)을 제공한다. 배점은 1 이상의 정수다.
- 배점의 기본값은 직전 문제의 배점이다. 첫 문제의 기본값은 10점이다.
- 라운드 진행 중 교사가 접수 순서 중 한 참가자를 고르고 **'정답'**을 누르면, 그 참가자(팀전은 그 팀)에게 이번 문제 배점이 점수판에 더해진다.
- 정답 반영은 문제당 한 번만 일어난다. 같은 버튼을 여러 번 눌러도 점수가 두 번 들어가지 않는다. 같은 문제에 여러 참가자의 공동 정답을 인정하려면 교사가 '추가 정답'을 명시적으로 선택해야 한다.
- 잘못 반영한 정답은 점수판의 '최근 조작 취소'로 되돌릴 수 있다(10절).
- '오답'은 점수를 바꾸지 않는다. 오답 감점 기능은 이번 버전에 포함하지 않는다.
- 점수판 변경 내역에는 "버저 3번 문제 정답 +100 (○○팀, 누른 학생 △△)"처럼 출처·문제 번호·배점이 남는다.
- 점수판을 연결하지 않은 버저는 정답·오답 판정만 하고 점수는 다루지 않는다.

**완료 기준:** 24명 동시 참여 시 중복 입력이 순위를 늘리지 않고, 라운드 종료 후 늦게 도착한 입력이 다음 라운드에 섞이지 않는다. 새로고침 후에도 같은 라운드에 두 번 참여할 수 없다. 라운드 시작 전에 누른 학생은 5초 동안 잠기고, 5초 뒤 같은 라운드에 정상 참여할 수 있다. 5점·100점 문제를 차례로 맞히면 점수판에 각각 5점·100점이 한 번씩 반영된다.

## 8 타이머와 스톱워치

### 8.1 타이머

시·분·초 입력, 자주 쓰는 시간 버튼, 시작·일시 정지·재개·초기화를 제공한다. 남은 시간을 크게 표시하고 종료 시 시각 알림과 선택 가능한 소리 알림을 제공한다. 종료 후 기본값은 0에서 정지이며 음수로 계속 흐르지 않는다. 실행 중 시간 추가·감소를 제공하되 현재 시간을 확인할 수 있고 0 미만으로 설정할 수 없다.

전체 화면 전환, 다른 탭 이동, 재접속 때문에 경과 시간이 초기화되거나 멈추지 않아야 한다. 교사가 일시 정지한 시간만 실제로 정지한다. 화면을 닫은 동안 이미 시간이 끝났다면 돌아왔을 때 종료 상태를 표시하며 알림이 반복해서 발생하지 않는다.

### 8.2 스톱워치

시작·일시 정지·재개·초기화·구간 기록을 제공한다. 총 경과 시간과 구간 기록을 구분해 표시한다. 구간 기록은 서버에 저장하지 않고 화면에서 확인한다(3.5절). 새로고침 후에도 실행 중이면 경과한 시간을 반영하며 일시 정지 중이면 시간을 유지한다.

**완료 기준:** 5분 타이머를 시작하고 1분 뒤 화면을 다시 열면 약 4분이 남아야 한다. 일시 정지 상태에서 기다린 시간은 경과 시간에 포함되지 않는다.

단계별 연속 타이머는 이번 버전 필수 범위에 포함하지 않는다.

### 8.3 순서 정하기와 발표 타이머 연결

순서 정하기 화면에서 '발표 타이머 켜기'를 선택하고 1인당 발표 시간을 정할 수 있다.

- 타이머는 순서 정하기 화면 안에 함께 표시된다. 별도 화면을 오가지 않아도 된다.
- '다음 사람'을 누르면 현재 참가자를 발표 완료로 표시하고, 다음 참가자를 강조하며, 타이머를 설정 시간으로 다시 시작한다.
- 타이머가 끝나도 다음 사람으로 자동으로 넘어가지 않는다. 교사·학생이 '다음 사람'을 눌러야 넘어간다.
- 발표 도중 일시 정지·시간 추가·초기화는 8.1절의 타이머 규칙을 그대로 따른다.
- 마지막 참가자가 끝나면 타이머를 멈추고 "모든 순서가 끝났어요"를 표시한다.
- 개인 도구끼리의 연결이므로 서버에 저장하지 않는다.

**완료 기준:** 6명 순서에서 1인 2분 타이머를 켜고 '다음 사람'을 5번 누르면 매번 타이머가 2분부터 다시 시작되고, 완료 표시가 5명에게 정확히 붙는다.

## 9 토너먼트 대진표

### 9.1 생성

개인·길드·직접 입력 팀·팀 만들기 결과를 참가자로 사용한다. 기본 방식은 단판 탈락 토너먼트이며 최소 2개 참가 단위가 필요하다. 무작위 배정과 교사의 수동 자리 배정을 제공한다. 생성 후 첫 경기 시작 전에는 배치를 수정할 수 있다.

참가 수가 2·4·8·16·32 등으로 맞지 않으면 필요한 부전승을 자동 배치한다. 부전승 수와 대상은 시작 전에 확인할 수 있어야 하며 무작위 편성 시 같은 조건으로 배정한다. 3위 결정전은 기본 꺼짐이며 시작 전에 켤 수 있다.

### 9.2 진행

각 경기에서 승자를 선택하면 다음 라운드의 해당 칸에 진출한다. 경기별 점수나 간단한 메모를 남길 수 있다. 아직 참가자가 정해지지 않은 경기는 승자를 선택할 수 없다. 결승 종료 후 우승자를 표시하고, 교사가 활동을 종료할 때까지 전체 결과를 유지한다(종료 후 보관하지 않음, 5.4절).

### 9.3 중계 화면과 학생 화면

- 교사가 대진을 확정하면 중계 화면과 학생 화면에서 **대진표가 만들어지는 연출**이 재생되고 최종 대진이 나타난다. 연출의 결과는 확정된 대진과 일치해야 한다(5.1절).
- 경기 승자가 정해질 때마다 두 화면의 대진표가 갱신되고, 결승이 끝나면 우승 연출을 보여준다.
- 학생 화면은 읽기 전용이며 승자 선택·메모 등 교사 조작은 보이지 않는다. 경기 메모는 교사가 공개를 켠 경우에만 보인다.
- 연출은 빠른 결과 보기로 건너뛸 수 있다(5.3절).

승자 오선택을 취소·변경할 수 있다. 그 변경으로 이후 경기 참가자가 달라지면 영향을 받는 후속 경기의 결과와 점수가 초기화됨을 알리고 확인한다. 다른 가지에서 정상적으로 끝난 경기는 유지한다. 동점은 자동 진출시키지 않고 교사가 재경기 등으로 승자를 정할 때까지 대기한다.

**완료 기준:** 5개 길드로 3개의 부전승이 있는 대진을 만들 수 있고, 초기 승자 정정 시 영향받는 후속 경기만 초기화된다.

## 10 팀 점수판

길드·학생·직접 입력 팀·팀 만들기 결과를 점수 항목으로 등록할 수 있다. 팀별 이름·색상과 선택 가능한 표식을 표시한다. 기본 점수는 0이며 +1·-1 빠른 조작, 임의 점수 증감, 점수 직접 수정을 제공한다. 음수 점수를 허용한다.

점수가 바뀔 때 어떤 팀에 얼마가 반영됐는지 확인할 수 있어야 한다. 최근 조작 취소, 팀별 변경 내역, 전체 점수 초기화가 가능하다. 동점은 공동 순위로 표시하고 다음 순위는 앞선 팀 수를 반영한다. 예를 들어 10점·10점·5점은 1위·1위·3위다.

고정된 팀 배치와 점수순 정렬을 선택할 수 있다. 기본값은 고정 배치로 하여 점수 변경 중 팀 위치가 갑자기 바뀌어 오조작하는 일을 줄인다. 학생 화면은 교사가 공유한 점수만 읽을 수 있으며 수정할 수 없다.

학생 화면과 중계 화면에는 각 팀의 이름·색상·점수·순위를 표시한다. 학생 화면에서는 자기가 속한 팀을 강조한다. 점수가 바뀌면 바뀐 팀에 짧은 변화 표시(예: +100)를 보여준다. 점수 변경 내역의 세부(누가 조작했는지, 취소 이력)는 교사 화면에만 표시한다.

선착순 버저와 연결된 점수판은 버저의 '정답' 판정으로도 점수가 바뀐다(7.3절). 버저 반영 점수도 일반 점수 변경과 똑같이 취소·내역 확인이 가능하다.

점수는 해당 활동 안에서만 사용한다. 골드·크리스탈·길드 기여도 등 B.R.A.N.D의 기존 자산이나 공식 점수로 자동 반영하지 않는다.

**완료 기준:** 팀 만들기 결과를 재입력 없이 불러오고, 오입력한 점수 변경만 취소하며, 종료 기록에서 최종 점수와 변경 내역을 확인할 수 있다.

## 11 투표

### 11.1 공통 설정 및 참여

교사는 투표 제목·설명·참여 대상·투표 방식·마감 방법·결과 공개 시점·익명 여부를 정한다. 마감은 교사 수동 마감이 기본이며 종료 시각을 지정한 자동 마감도 제공한다. 활동 시작 후 선택지와 투표 규칙을 바꾸려면 해당 투표를 취소하고 새 투표를 만들어야 한다.

참여 대상은 해당 학급 전체 또는 선택한 학생이다. 한 계정은 한 장의 투표만 제출할 수 있다. 마감 전에는 본인 투표를 수정할 수 있으며 최종 제출 내용만 집계한다. 여러 기기나 새로고침으로 표가 늘어나지 않는다. 마감 후에는 제출·수정을 막는다.

교사에게 전체 대상 수·참여 수·미참여 수와 미참여자 목록을 표시한다. 학생 화면과 중계 화면에는 참여 수만 표시하고 다른 학생의 참여 여부를 개별 공개하지 않는다. 기본값은 익명 투표, 마감 후 교사 확인 및 공개 버튼으로 결과 발표다.

익명 투표는 **학생 화면·중계 화면에서 누가 어떤 선택을 했는지 보여주지 않는 방식**이다. 교사는 오류를 바로잡기 위해 교사 운영 화면에서 **학생별 선택 내용을 확인할 수 있다.**

- 학생별 선택은 교사 운영 화면의 별도 '학생별 투표 확인' 영역에서만 보인다. 이 영역은 기본으로 접혀 있고, 중계 화면이나 발표용 전체 화면에는 어떤 경우에도 나타나지 않는다. 수업 중 교사 화면을 교실에 띄워도 실수로 노출되지 않게 한다.
- 학생 안내 문구는 다음을 기본으로 한다: **"누가 무엇을 골랐는지 다른 친구들은 알 수 없어요."** 투표 화면의 제출 버튼 근처에 항상 표시한다.
- 학생에게 "운영국도 알 수 없어요", "완전 비밀" 같은 사실과 다른 안내를 하지 않는다.

기명 투표는 결과 공개 시 교사가 선택하면 **개인별 선택까지 중계 화면에 공개할 수 있는 방식**이다. 기명 여부는 투표 시작 전에 정하고, 학생에게 "이 투표는 누가 무엇을 골랐는지 공개될 수 있어요"를 안내한다. 기명 투표라도 학생 화면과 중계 화면에 개인별 선택을 자동 공개하지 않는다.

**오류 정정:** 교사는 학생의 표 내용을 다른 선택으로 바꿀 수 없다(5.4절). 마감 전이면 학생이 직접 수정하도록 안내하고, 마감 후 잘못된 표가 확인되면 교사는 그 표를 **무효 처리**할 수 있다. 무효 처리에는 사유 메모가 필수이며, 무효 처리한 표는 집계에서 빠지고 기록에 사유·시각과 함께 남는다. 무효 처리는 결과 공개 전에만 가능하며, 공개 후 정정이 필요하면 새 회차 투표로 진행한다.

결과 공개 방식을 ‘진행 중 공개’로 바꿀 수 있으나 시작 전에 결정한다. 비공개 결과를 학생이 미리 볼 수 없어야 한다. 투표를 마감하면 해당 회차를 다시 열지 않으며 추가 투표가 필요하면 새 회차를 만든다.

### 11.2 찬반 투표

선택지는 찬성·반대가 기본이며 기권 선택지를 켤 수 있다. 기권 제출과 미참여는 구분한다. 결과에는 선택지별 표수, 총 참여 수, 미참여 수를 표시한다. 선택지별 비율의 분모는 기권을 포함한 전체 제출표 수이며 화면에 기준을 표시한다.

기본 결과는 득표 현황만 제공하고 가결·부결을 임의 판단하지 않는다. 교사가 자동 판정을 켜는 경우에만 가결 기준을 설정한다. 기준은 ‘전체 투표 대상 중 정해진 인원 이상 찬성’ 또는 ‘유효 찬반표 중 과반 찬성’ 중 선택한다. 후자는 기권을 분모에서 제외하며 동수이면 과반이 아니다. 기준·분모·필요 찬성표를 시작 전과 결과 화면에 표시한다.

### 11.3 후보자 선출 투표

경제수호대 등 선출할 직책과 후보를 등록하고 선출 인원 및 한 사람이 선택할 수 있는 최대 후보 수를 설정한다. 후보는 실제 학생 명단에서 선택하며 같은 학생을 중복 등록할 수 없다. 이번 버전에서 후보 등록·확정은 교사가 수행한다.

기본값은 후보 1명 선택, 선출 1명이다. 여러 명 선출 시 중복 선택 없이 최대 선택 수 이내에서 제출할 수 있다. 후보를 선택하지 않는 경우에는 별도의 기권을 선택해야 하며 빈 제출은 허용하지 않는다. 기권과 후보 선택을 동시에 할 수 없다. 후보자 본인의 투표도 허용한다.

선출 인원·최대 선택 수는 후보 수보다 클 수 없다. 결과에는 후보별 득표수와 순위를 표시하고, 득표 비율을 표시할 경우 ‘후보 선택 유효 투표자 수’를 분모로 사용한다. 복수 선택 투표는 비율 합계가 100%를 넘을 수 있다는 설명을 붙인다. 기권 수는 별도로 표시한다.

당선 경계에서 동률이 발생하면 임의로 당선자를 정하지 않는다. 당선이 확정된 후보는 보존하고, 남은 자리를 두고 동률 후보만 새 결선 투표를 만들 수 있다. 결선에서도 동률이면 미확정으로 남기고 추가 결선 또는 교사 판단으로 활동을 마친다. 교사 판단은 투표 결과를 고치는 것이 아니라 별도의 결정 메모로 남긴다. 유효 후보 선택표가 0표이면 당선자를 자동 확정하지 않는다.

선출 결과를 기존 경제수호대 권한이나 직책에 자동 적용하지 않는다. 기존 직책 변경은 교사가 별도로 수행한다.

**완료 기준:** 24명 중 19명이 참여하면 참여 19·미참여 5로 표시된다. 익명 투표에서 교사는 운영 화면에서 미참여자와 학생별 선택을 확인할 수 있고, 학생 화면과 중계 화면에는 개인별 선택이 나타나지 않는다. 2명 선출에서 1위는 확정하고 공동 2위 후보만 결선으로 넘길 수 있다.

### 11.4 다지선다 투표

학급 안건처럼 여러 선택지 중에서 고르는 일반 투표다. 예: 체험학습 장소, 학급 행사 메뉴.

- 선택지는 2개 이상, 최대 12개(운영 기본값)까지 교사가 직접 입력한다. 선택지 문구는 1~40자이며 같은 문구를 중복 등록할 수 없다.
- 선택지마다 짧은 설명(선택)을 붙일 수 있다.
- 한 사람이 고를 수 있는 개수(기본 1개, 최대 선택지 수)를 정한다. 여러 개 선택 투표는 선택 수 이내에서 제출하며, 비율 합계가 100%를 넘을 수 있다는 설명을 붙인다.
- 기권 선택지를 켤 수 있다. 기권과 다른 선택지는 함께 고를 수 없다. 빈 제출은 허용하지 않는다.
- 결과에는 선택지별 표수·순위·비율, 총 참여 수, 기권 수, 미참여 수를 표시한다. 비율의 분모는 기권을 제외한 유효 투표자 수이며 화면에 기준을 표시한다.
- 1위 동률이면 임의로 정하지 않고 동률 선택지만으로 결선 투표를 만들 수 있다(11.3절의 결선 규칙과 같다).
- 선택지 표시 순서는 교사가 입력한 순서가 기본이며, 학생마다 순서를 섞어 보여주는 옵션을 제공한다.
- 공통 규칙(익명·기명, 마감, 결과 공개, 오류 정정)은 11.1절을 따른다.

**완료 기준:** 선택지 4개·1개 선택 투표에서 24명이 제출하면 선택지별 표수 합계가 기권을 포함해 24가 된다. 1위가 2개 선택지로 동률이면 두 선택지만으로 결선을 만들 수 있다.

## 12 팀 만들기와 발표 카드 구름

### 12.1 팀 만들기

**입력:** 참가자 목록, 팀당 희망 인원, 남는 인원 처리 방식.

학생·자유 입력 참가자를 선택하고 팀당 몇 명으로 구성할지 입력한다. 길드 구성원 일괄 추가를 지원한다. 길드 자체나 기존 팀을 참가 단위로 추가하면 그 항목을 쪼개지 않고 하나의 단위로 취급하며, 화면에서는 ‘명’ 대신 ‘항목’으로 안내한다.

팀당 인원은 1 이상 정수이며 참가자 수보다 클 수 없다. 시작 전 예상 팀 수와 팀별 인원을 보여준다. 남는 인원 처리 기본값은 가능한 균등하게 배분이며 별도 대기 인원으로 두는 방식도 선택할 수 있다.

- **균등 배분:** 희망 인원을 넘지 않도록 필요한 팀 수를 정한 뒤 팀별 인원 차이가 최대 1이 되게 구성한다. 23명·팀당 4명이면 4명 팀 5개와 3명 팀 1개다. 25명·팀당 4명이면 4명 팀 4개와 3명 팀 3개다.
- **별도 대기:** 희망 인원에 맞는 팀만 만들고 나머지는 대기 명단에 둔다. 23명·팀당 4명이면 4명 팀 5개와 대기 3명이다.

무작위 편성 후 팀 이름·색상을 수정하고 참가자를 다른 팀이나 대기 명단으로 옮길 수 있다. 터치 환경에서도 선택 후 이동할 팀을 누르는 방식으로 조정할 수 있어야 한다. 수동 조정으로 인원이 불균등해지면 현재 인원을 보여주되 조정을 막지 않는다. 같은 참가자가 두 팀에 들어가거나 이동 중 사라져서는 안 된다.

전체 다시 섞기는 확인 후 새 편성으로 진행한다. 팀 점수판·토너먼트 대진표로 보내기 전에 대기 인원이 제외됨을 표시한다. 전달할 때 팀 이름·색상·구성원을 함께 보존하고 대상 활동에서 최종 확인 후 시작한다. 한 활동에서 팀을 수정해도 이미 시작한 다른 활동의 팀 구성이 자동 변경되지 않는다.

**완료 기준:** 23명·4명 설정에서 예상 구성이 생성 결과와 일치한다. 수동 이동 후에도 23명 전원이 팀 또는 대기 명단에 한 번씩 존재하며 팀 이름 재입력 없이 점수판을 열 수 있다.

함께 배치·분리 배치, 성별·성적·능력에 따른 균형 편성은 이번 버전 필수가 아니다.

### 12.2 발표 카드 구름

**목적:** 학생의 생각을 제목 카드로 한눈에 모아 보고, 교사가 카드를 골라 상세 내용을 확인하고 발표를 진행한다. 단어 출현 빈도를 크기로 표현하는 워드 클라우드가 아니다.

교사는 활동 제목·안내 문구·참여 대상·작성자 표시 여부를 설정하고 제출을 연다. 학생은 제목과 내용을 입력한다. 기본적으로 학생 1명당 카드 1개이며 제출을 닫기 전에는 자신의 카드를 수정할 수 있다. 제목은 1~40자, 내용은 1~2,000자로 하며 앞뒤 공백을 제외하고 계산한다. 글자 수와 남은 입력 가능량을 표시한다.

학생은 자기 화면에서 제목과 내용을 입력해 제출한다. 학생이 제출하면 교사 운영 화면과 교사 중계 화면(발표 화면)에 제목 카드가 나타난다. 다른 학생의 카드는 학생 화면에 보이지 않는다. 기본값은 작성자 이름 표시이며 교사가 숨길 수 있다. 작성자 숨김은 발표 화면의 표시만 숨기는 기능으로, 교사는 제출 관리 화면에서 작성자를 확인할 수 있다. 학생에게도 이 차이를 안내한다.

카드들은 화면 안에 구름처럼 모이되 제목이 읽히고 선택할 수 있게 배치한다. 등장할 때만 부드럽게 움직이고 이후 자리를 유지한다. 카드 수가 늘어도 서로를 가려 선택 불가능해지면 안 된다. 카드 구름 보기와 정렬된 목록 보기를 전환할 수 있고 전환해도 제출·발표 상태를 유지한다.

교사가 카드를 누르면 제목·내용이 크게 펼쳐지며 긴 내용은 스크롤로 끝까지 볼 수 있다. 닫으면 원래 카드 위치로 돌아온다. 제출 중 카드 내용이 수정되면 변경 표시를 하고 현재 읽는 내용을 갑자기 교체하지 않는다. 교사가 최신 내용으로 갱신할 수 있게 한다.

교사는 발표 완료 표시·취소, 미발표 카드만 보기, 제목·내용·작성자 검색, 미발표 카드 중 무작위 선택을 할 수 있다. 무작위 선택은 발표 완료 카드를 제외하며, 선택만으로 발표 완료 처리하지 않는다. 모든 카드가 발표 완료이면 선택할 대상이 없다고 알린다.

교사는 제출 수·미제출 수와 미제출자 목록을 확인한다. 부적절하거나 발표에 사용할 수 없는 카드는 숨김·복원할 수 있으며 학생 원문을 교사가 몰래 수정하지 않는다. 숨긴 카드는 발표 화면과 무작위 선택 대상에서 제외하고, 교사 운영 화면에서는 활동이 끝날 때까지 원문과 숨김 상태를 확인할 수 있다.

제출 닫기는 신규 제출과 수정만 막으며 교사의 카드 열람·발표 진행은 계속 가능하다. 활동을 종료하면 제출 내용과 발표 상태는 보관하지 않는다(5.4절). 종료 전에 "카드 내용이 모두 사라져요"를 확인받는다. 학생에게 모든 카드의 본문을 둘러보는 공동 게시판 기능은 이번 버전 필수가 아니다.

**완료 기준:** 24명이 각자 제출하면 제목 카드 24개가 누락 없이 표시되고 모든 카드를 선택할 수 있다. 한 학생이 수정·새로고침해도 카드가 추가 생성되지 않으며 작성자 숨김 상태로 전체 화면을 열면 이름이 노출되지 않는다.

## 13 도구 간 연결과 범위 제한

### 13.1 필수 연결

| 출발 | 도착 | 전달 항목 |
| --- | --- | --- |
| 공통 참가자 명단 | 참가자 선택이 필요한 다른 도구 | 종류·이름·실제 참가자 연결·선택된 구성원 |
| 팀 만들기 | 팀 점수판 | 팀 이름·색상·구성원, 점수는 0으로 시작 |
| 팀 만들기 | 토너먼트 대진표 | 팀 이름·색상·구성원 |
| 팀 만들기 | 선착순 버저 | 팀 이름·구성원, 대표 또는 전원 참여 설정 확인 |
| 선착순 버저 | 팀 점수판 | 문제별 배점, 정답 판정 시 해당 참가자·팀에 배점 반영(7.3절) |
| 순서 정하기 | 타이머 | 1인당 발표 시간, '다음 사람' 시 타이머 다시 시작(8.3절) |

팀 만들기에서 학급 활동(점수판·대진표·버저)으로 보내기는 **교사 운영 패널에서 만든 팀에만** 제공한다. 학생이 개인 도구로 만든 팀은 그 학생 화면 안에서만 쓰인다.

도구로 보내기는 새로운 대상 활동을 준비하는 동작이다. 원본 활동의 기록을 바꾸거나 기존 진행 중 활동에 덮어쓰지 않는다. 추첨 결과·점수·투표 결과를 다른 도구에 임의 적용하지 않는다. 단, 버저와 연결한 점수판에는 교사의 '정답' 판정으로만 점수가 들어간다.

### 13.2 이번 버전에 포함하지 않는 기능

- 새로운 골드·크리스탈 지급, 자산 차감, 길드 기여도 반영, 공식 직책 자동 변경.
- 외부 비로그인 참가자 입장 코드 및 별도 손님 계정 체계.
- 단계별 연속 타이머, 리그전·패자부활전·더블 엘리미네이션.
- 자리 배치, 자동 역할 배정, 감정 체크, 출구 티켓, 선택·신청 보드.
- 성별·성적 기반 팀 균형 조정, 특정 학생 함께·분리 배치 조건.
- 한 사람이 만든 제비를 여러 학생 기기에서 나눠 뽑는 공유 제비, 카드 댓글·좋아요·첨부파일.
- 여러 활동에 걸쳐 최근 뽑힌 학생을 자동 제외하는 쏠림 방지 기능(필요 없음으로 결정).
- 버저 오답 감점.

이 항목들은 추후 확장 후보이며 이번 완료 판정에서 요구하지 않는다.

## 14 활동 기록

기록으로 보관하는 도구는 **투표와 팀 점수판 두 가지뿐**이다. 나머지 도구는 활동이 끝나면 보관하지 않는다(5.4절). 이렇게 해서 저장 용량 부담을 줄인다.

교사는 도구 종류·활동 제목·날짜로 기록을 찾아 다시 열 수 있어야 한다. 기록에는 당시 참가자와 설정, 확정된 결과, 생성·시작·종료 시각을 남긴다. 종료한 활동은 기본적으로 읽기 전용이며 같은 설정으로 새 활동 만들기를 제공한다.

| 도구 | 보존해야 할 주요 내용 |
| --- | --- |
| 팀 점수판 | 팀 구성·최종 점수·점수 변경 및 취소 내역(버저 정답 반영분은 문제 번호·배점·누른 학생 포함) |
| 투표 | 투표 규칙·참여 현황·학생별 선택·집계·무효 처리 내역과 사유·결선 관계·결정 메모 |

| 보관하지 않는 도구 | 처리 |
| --- | --- |
| 개인 도구 6종(제비뽑기·사다리타기·룰렛·순서 정하기·타이머·스톱워치·팀 만들기) | 처음부터 서버에 저장하지 않음 |
| 선착순 버저·토너먼트 대진표·발표 카드 구름 | 활동 중에만 저장, 종료 시 정리 |

학생별 투표 선택은 익명 투표라도 교사가 기록 화면에서 확인할 수 있다(11.1절). 학생 화면과 중계 화면에서는 기록을 열 수 없다. 기록 삭제는 교사만 가능하며 삭제될 활동을 확인한 뒤 수행한다. 활동 종료나 기록 삭제가 학생 계정·길드·재화 기록을 변경해서는 안 된다. 파일 내보내기는 이번 버전 필수 범위에 포함하지 않는다.

## 15 예외 처리와 사용 품질

- 참가자 0명, 빈 입력, 수량 불일치, 선택 가능 인원 초과 등은 실행 전에 해당 위치에서 구체적으로 안내한다.
- 진행 중 명단·규칙을 변경할 수 없다면 이유와 가능한 다음 동작을 표시한다.
- 같은 버튼을 연속으로 눌러도 활동·결과·점수가 의도치 않게 여러 번 생성되지 않는다. 점수의 정상적인 여러 차례 조작과 중복 요청은 구분한다.
- 접속이 끊기면 학생에게 재접속 상태를 표시하고 버저·투표·카드 제출이 접수됐는지 확인할 수 있게 한다. 미확정 버저 입력을 접수된 것처럼 보이지 않는다.
- 학생에게 열려 있는 참여형 활동이 종료되면 버튼을 비활성화하고 종료 상태를 안내한다.
- 여러 교사 화면에서 같은 활동을 열더라도 마지막 확정 상태를 함께 보여주고 충돌 시 다른 변경을 조용히 덮어쓰지 않는다.
- 24명 학급 전체가 참여하는 상황과 길드 전체를 한 번에 사용하는 상황을 기본 사용 규모로 검증한다. 학생 24명·현재 길드 수를 고정 제한으로 만들지 않는다.
- 교사용 PC 발표 화면과 학생 크롬북·휴대전화·태블릿에서 필수 기능을 사용할 수 있어야 한다. 색상만으로 선택·완료·당첨 여부를 구분하지 않는다.
- 도구함을 사용하지 않을 때까지 과도한 화면 갱신이나 소리·연출이 계속되지 않아야 한다.
- 학생에게 보이는 오류는 기술적인 오류 문구 대신 이해할 수 있는 한글 안내로 보여주고, 교사 화면에서는 실제 원인을 확인할 수 있게 한다.
- 새 화면의 제목·라벨·본문·도움말은 흐린 회색 글씨를 쓰지 않는다. 어두운 배경에서는 밝은 아이보리·크림 계열 등 충분히 대비되는 색을 쓴다.

### 15.1 실시간 부하 기준

지난 경매·레이드에서 24명 동시 접속 시 렉이 반복된 경험이 있으므로, 도구함은 처음부터 다음 기준을 만족해야 한다.

- **개인 도구는 사용 중 서버와 통신하지 않는다.** 학급 명단·길드를 불러올 때만 한 번 읽는다.
- **학생 화면은 전체 상태를 일정 간격으로 계속 다시 묻지 않는다.** 활동이 바뀐 순간에 알림을 받고, 바뀐 부분만 받는다. 학급 활동이 없는 동안에는 도구함 관련 조회가 홈 화면 성능에 영향을 주지 않아야 한다.
- 학생 홈의 '모험가 도구함' 배지(3.2절)는 홈 로그인 경로를 무겁게 만들지 않는다.
- 버저는 가장 짧은 시간에 입력이 몰리는 도구다. 24명이 0.5초 안에 동시에 누르는 상황에서도 순서 판정이 지연·누락되지 않아야 하며, 순서 판정은 서버가 한다.
- 버저 판정, 투표 제출·집계, 점수 변경, 카드 제출처럼 중요한 저장은 학생 기기의 계산을 믿지 않고 서버에서 검증한다.
- 실시간 알림 방식은 기존 경매·레이드 방식과 섞지 않고 도구함 전용으로 설계하며, 설계 내용을 구현 전에 보고한다(부록 A.4).
- 중계 화면을 켜 둔 상태에서도 학생 화면 반응이 느려지지 않아야 한다.

**검증:** 운영 학급과 분리된 부하 테스트 학급(B.R.A.N.D LOADTEST)에서 24명 규모로 버저·투표·카드 구름을 검증한다. 기준 환경은 학생 기기 RAM 4GB급 크롬북, 5GHz 와이파이, 교사 중계 PC 1대다. 기존 경매·레이드·아케이드 부하 테스트 도구와 같은 방식의 도구함용 부하 테스트를 준비한다.

| 검증 항목 | 통과 기준(운영 기본값) |
| --- | --- |
| 버저 동시 입력 24건 | 누락·중복 0건, 교사·중계 화면에 순서 표시까지 1초 이내 |
| 투표 동시 제출 24건 | 누락·중복 0건, 참여 수 갱신 2초 이내 |
| 카드 동시 제출 24건 | 누락·중복 0건, 중계 화면 표시 3초 이내 |
| 점수 변경 | 학생·중계 화면 반영 2초 이내 |
| 중계 화면 켠 상태 | 위 기준 모두 유지 |

아래 항목을 모두 충족해야 이번 기능 범위의 구현이 완료된 것으로 본다.

- [ ] 모험가 도구함 이름으로 11개 도구에 접근할 수 있다.
- [ ] 학생 홈 상단 메뉴 줄의 '기록실' 바로 왼쪽에 '모험가 도구함' 버튼이 있고, 데스크톱·모바일 폭 모두에서 잘리지 않는다.
- [ ] 학생은 개인 도구 6종을 혼자 쓸 수 있고, 그 결과는 서버에 저장되지 않는다.
- [ ] 점수판·대진표·투표·카드 구름·버저의 교사 설정 화면, 교사 중계 화면, 학생 화면이 분리되어 있다.

## 17 구현 전달 지침

이 문서에 정의한 사용자 동작과 결과를 구현 기준으로 사용한다. 구체적인 기술 설계는 구현 담당자가 현재 프로젝트를 확인해 결정한다. 기존 기능과 연결할 수 없는 요구가 발견되면 기능을 완료했다고 처리하지 말고, 어느 사용자 동작이 막히는지와 대안을 보고한다. 선택적 확장 기능을 먼저 구현하느라 이 문서의 필수 범위를 누락하지 않는다.

구현 시 저장소의 `AGENTS.md` 규칙을 함께 따른다. 이 문서와 관련된 핵심은 다음과 같다.

- 기존 학생·길드·길드원·출석 정보는 **읽기만** 한다. 도구함 때문에 이 정보를 수정하지 않는다.
- 운영 DB는 로컬 migration 폴더보다 앞서 있으므로, 새 저장 구조를 만들기 전에 실제 운영 DB 상태를 먼저 확인한다. 변경은 항상 새 증분 migration으로 하며 기존 기록을 지우지 않는다.
- 중요한 쓰기(투표 제출·집계·무효 처리, 점수 변경, 버저 판정, 카드 제출)는 서버 함수 안에서 권한·학급 범위·참가 자격을 검증한다.
- AI는 `npm install`·`npm ci`·`npm run build`를 실행하지 않는다. 빌드는 사용자가 로컬에서 직접 하고, AI는 결과를 받아 수정한다.
- 패치를 전달할 때마다 Git commit용 Summary와 Description 문구를 함께 제시한다.
