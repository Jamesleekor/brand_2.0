# 경매 낙찰품 정리 v1 (2026-10-30)

## 무엇인가
본 경매가 끝난 뒤, 한 학생이 같은 카테고리(자리·1인1역·급식순서) 상품을 2개 이상 낙찰받았을 때
운영국(교사)이 교사 패널에서 정리하는 기능. 학생 1명은 카테고리마다 1개만 가질 수 있다.

## 확정 규칙 (사용자 결정 2026-10-29)
1. **무료 양도**: 2개 이상 가진 학생은 남는 상품을 원하는 친구에게 무료로 넘긴다.
   받는 친구가 이미 상품을 가지고 있어도 되며, 그 친구도 다시 1개가 되도록 정리해야 한다.
2. **강제 분배**: 무료 양도하지 않은 남는 상품은 그 카테고리 상품이 0개인 학생 중 1명에게 랜덤으로 간다.
   - 받은 학생은 낙찰가를 운영국에 낸다. 부족하면 낼 수 있는 만큼 내고 나머지는 자산 미납(`student_asset_arrears`)으로 기록한다.
   - 운영국은 낙찰가의 50%(소수점 버림)를 **최초 낙찰자**에게 수수료로 지급한다. 소득세 없음.
3. **최종 유찰품**: 0개인 학생 중 1명에게 랜덤 분배. 가격은 이전 회차 낙찰가(같은 학급·카테고리·상품명의 가장 최근 낙찰).
   이전 낙찰 기록이 없으면 그 상품의 시작가. 수수료 없음.
4. 정리가 끝나면 카테고리별·학생별 최종 배치표를 본다.

## 구현 메모
- 기존 경매 기록(`auction_results` 등)은 수정하지 않는다. 정리 결과는 새 장부 3개에만 쌓인다.
  - `auction_settlement_categories` / `auction_settlement_items` / `auction_settlement_events`
- 교사 RPC: `teacher_auction_settlement_state / _transfer / _mark_forced / _undo / _finalize`
- 학생이 1개뿐인 상품은 양도·강제 분배할 수 없다(1개는 반드시 남김).
- 정리 중(OPEN)에는 무료 양도·강제 분배 지정을 되돌릴 수 있다. 최종 확정(FINALIZED) 후에는 바꿀 수 없다.
- 추첨·대금 징수·수수료 지급은 `teacher_auction_settlement_finalize` 한 번의 트랜잭션에서 처리한다.
- 수수료(양수 GOLD)를 받는 학생에게 미납금이 있으면, 기존 `create_transaction` 규칙대로 미납금이 먼저 자동 징수된다.
- 정리 장부가 생긴 회차는 FK 때문에 "같은 회차 초기화(reset)"가 막힌다. 정리 과정의 돈 기록이 초기화로 꼬이지 않게 하려는 의도된 보호다.
- 1인1역 실제 배정표(`primary_jobs`), 길드5 영토세는 이 기능과 연결하지 않았다(원래 낙찰 기록 기준 그대로).

## 적용 순서
1. Supabase SQL Editor에서 `supabase/APPLY_AUCTION_SETTLEMENT_V1_20261030.sql` 실행
2. 프런트 코드 push → GitHub Actions 배포

## E2E 점검표 (교사 로그인 상태)
- [ ] 교사 패널 → 경매 → 이전 경매 기록 → 회차 열기 → "🧩 낙찰품 정리" 버튼이 보인다
- [ ] 정리 화면이 열리고, 2개 이상 가진 학생 목록이 나온다
- [ ] 1개 가진 친구에게 무료 양도 → 그 친구가 "정리가 필요한 학생"에 새로 나타난다
- [ ] 무료 양도 기록에서 "마지막 양도 취소"가 된다
- [ ] 강제 분배 지정 → "랜덤 분배 대기"로 이동, "되돌리기"가 된다
- [ ] 정리 안 된 학생이 남아 있으면 최종 확정 버튼이 막혀 있다
- [ ] 최종 확정 → 랜덤 분배 결과(납부/미납/수수료)가 보인다, 확정 배지가 붙는다
- [ ] 받은 학생 거래내역에 `[낙찰품 강제 분배]`, 최초 낙찰자에게 `[강제 분배 수수료]`가 찍힌다
- [ ] 골드 부족 학생은 미납 관리 화면에 미납이 생긴다
- [ ] 📋 최종 배치표에서 학생별/상품별로 결과를 볼 수 있다
