## 3. 구조

### 3.1 서버 (전부 새 객체, 기존 표는 읽기만)

| 표 | 용도 | 활동 종료 시 |
| --- | --- | --- |
| `toolbox_activities` | 학급 활동 1건 (종류·상태·설정·참가자 고정본·진행 상태) | 버저·대진표·카드는 행 삭제, 투표·점수판은 `ENDED`로 보관 |
| `toolbox_buzzer_presses` | 라운드별 접수 순서 | 함께 삭제 |
| `toolbox_buzzer_locks` | 부정출발 5초 잠금 | 함께 삭제 |
| `toolbox_score_events` | 점수 변경 이벤트 (취소는 `undone_at`) | 점수판 기록으로 보관 |
| `toolbox_vote_ballots` | 학생별 표 (교사만 RPC로 조회) | 투표 기록으로 보관 |
| `toolbox_cards` | 학생 카드 | 함께 삭제 |
| `toolbox_rosters` | 교사 저장 명단·최근 명단(5개) | — |

- 내부 함수는 `brand_toolbox` 스키마 (authenticated 실행 불가).
- 공개 RPC 19개 모두 `SECURITY DEFINER` + 고정 `search_path`, 교사/학생 신원·학급 범위 검증.
- 오류 코드: `P7T01` 권한 · `P7T02` 대상 없음 · `P7T03` 상태 · `P7T04` 입력값 · `P7T05` 이미 처리됨. 메시지는 학생이 읽을 수 있는 한국어.
- 7일 넘게 방치된 버저·대진표·카드는 교사가 도구함 첫 화면을 열 때 정리 (cron 추가 없음).

### 3.2 실시간 설계 (경매·레이드와 섞지 않음)

- 상태가 바뀌면 서버가 `toolbox_pulse`의 `<학급>-S`(학생용) / `<학급>-T`(교사용) 행의 `rev`만 올린다.
- 화면은 이 행 하나만 `postgres_changes`로 구독하고, 신호가 왔을 때만 필요한 RPC 한 번을 다시 부른다.
  학생 쪽은 0~0.9초 무작위 지연으로 24명이 같은 순간에 읽지 않게 퍼뜨린다.
- 버저 입력·카드 제출·투표 제출 신호는 **T 행만** 바꾼다 → 학생 24명에게 퍼지지 않는다.
- 라운드 열림은 S 행 `payload`에 라운드 번호·상태를 실어, 학생 버저가 다시 읽기를 기다리지 않고 바로 켜진다.
- 실시간 연결이 끊긴 동안에만 10초 간격으로 신호 행을 확인한다.
- `student_toolbox_buzz`는 `client.ts`의 빠른 경로 목록에 추가(일반 대기열 2칸 뒤에 서지 않음).
- 개인 도구 6종은 서버와 통신하지 않는다(명단을 처음 읽을 때 제외). 기기 `localStorage`에만 임시 보관.
