# B.R.A.N.D. 2.0 — 월간 MVP 기초 데이터 기록실 구현 확정 명세

- 문서 상태: **LOCKED / 구현 기준**
- 작성일: 2026-09-11
- 기능명: **MVP 기초 데이터**
- 위치: **교사 운영 패널 → 분석 & 관리 → 통계 & 기록과 로그인 히스토리 사이**
- 목적: 월간 MVP 예선 진출자 12인 선정에 필요한 정량·정성 데이터를 한 화면에서 계산, 비교, 기록, 확정, 재열람한다.
- 원칙: 이 문서에서 정의된 데이터 의미와 저장 정책을 구현 중 임의 변경하지 않는다.

---

# 1. 기능 목표

기존에는 교사가 월간 MVP 후보를 선정할 때 여러 데이터를 개별 화면에서 복사하여 직접 계산했다.

MVP 예선 도입으로 후보가 12명까지 확대되므로, 다음을 한곳에서 처리하는 전용 기록실을 만든다.

1. 평가기간과 비교기간을 직접 지정한다.
2. 현재 학급 활성 학생 전체의 정량 데이터를 자동 계산한다.
3. 교사가 예선 진출 후보 12명을 직접 선택한다.
4. 각 학생의 수업 참여 4개 항목을 교사가 정성평가한다.
5. 학생별 특이사항/비고를 기록한다.
6. 필요하면 학생별 상세 근거 데이터를 확인한다.
7. 초안 단계에서는 재계산할 수 있다.
8. 최종 확정 시 당시 데이터를 **불변 스냅샷**으로 저장한다.
9. 과거 MVP 회차의 기초 데이터를 언제든 다시 열람한다.

이 기능은 **MVP를 자동 선정하거나 종합점수를 자동 산출하는 기능이 아니다.**

최종 판단은 반드시 교사가 한다.

# 4. 회차 상태

회차는 두 상태만 사용한다.

## 4.1 DRAFT

초안 상태.

가능:

- 평가기간 변경
- 비교기간 변경
- 자동 통계 재계산
- 예선 후보 선택/해제
- 수업 참여 평가 입력/변경
- 비고 입력/변경
- 학생 상세보기
- 임시 저장

자동 통계는 현재 DB 데이터를 기준으로 재계산할 수 있다.

---

## 4.2 FINALIZED

최종 확정 상태.

확정 순간의 데이터를 **스냅샷으로 고정**한다.

확정 후:

- 평가기간 변경 금지
- 비교기간 변경 금지
- 자동 통계 재계산 금지
- 예선 12인 변경 금지
- 정성평가 변경 금지
- 비고 변경 금지

이후 원본 DB에서 BV, 업적, 서비스 기록 등이 수정되어도 **확정된 과거 MVP 회차 값은 변경되지 않는다.**

과거 자료의 신뢰성을 위해 FINALIZED 회차를 실시간 데이터로 다시 계산하지 않는다.

# 5. 기간 설정

각 회차에는 서로 독립적인 두 기간이 있다.

## 5.1 평가기간

해당 MVP 선정을 위해 실제 성과를 집계할 기간.

예:

`2026-09-01 ~ 2026-09-30`

---

## 5.2 비교기간

BV 성장률 계산을 위한 이전 비교 기간.

예:

`2026-08-01 ~ 2026-08-31`

비교기간은 시스템이 자동으로 “지난달 1일~말일”로 고정하지 않는다.

**교사가 직접 시작일과 종료일을 선택한다.**

이는 실제 MVP 운영기간이 매달 동일하지 않을 수 있기 때문이다.

---

## 5.3 날짜 기준

모든 날짜형 기간은 **Asia/Seoul(KST)** 기준.

시작일은 해당 날짜 `00:00:00 KST` 포함.

종료일은 해당 날짜의 다음 날 `00:00:00 KST` 미만.

즉 양쪽 날짜 모두 사용자 관점에서 포함된다.

# 9. BV 집계 규칙

## 9.1 메인 BV

메인 표의 `획득 BV`는 평가기간 동안 학생이 **양수로 획득한 BV의 총합**이다.

계산 개념:

`평가기간의 BV 양수 증가량 합계`

페널티로 차감된 BV는 메인 `획득 BV`에서 빼지 않는다.

이유:

MVP 기초 데이터의 목적은 해당 기간 학생이 **얼마나 성과를 쌓았는가**를 보는 것이기 때문이다.

---

## 9.2 상세 BV

학생 상세보기에서는 다음을 모두 표시한다.

- 획득 BV
- 차감 BV
- 순증 BV

계산:

`순증 BV = 획득 BV - 차감 BV`

차감 BV는 절대값 형태로 표시.

예:

- 획득 `+4,550`
- 차감 `-500`
- 순증 `+4,050`

---

# 10. BV 성장률

성장률은 현재 총 BV의 성장률이 아니다.

**이번 평가기간의 획득 BV가 비교기간의 획득 BV보다 얼마나 증가/감소했는가**를 의미한다.

계산식:

`((평가기간 획득 BV - 비교기간 획득 BV) / 비교기간 획득 BV) × 100`

예:

- 비교기간 획득 BV: 4,000
- 평가기간 획득 BV: 5,000

→ `+25.0%`

---

## 10.1 비교기간 BV가 0인 경우

- 비교기간 0, 평가기간 > 0 → `NEW`
- 비교기간 0, 평가기간 0 → `0.0%`

무한대/Infinity/NaN을 표시하지 않는다.

---

# 11. 일일퀘스트 완수율

일일퀘스트 완수율은 다음처럼 계산한다.

`완료한 대상 일수 / 실제 일일퀘스트 대상 일수 × 100`

## 분모

다음 조건을 모두 만족하는 날짜만 포함한다.

- 평가기간 안의 날짜
- 해당 학생이 당시 활성 학생
- 해당 날짜에 실제 일일퀘스트가 운영 대상이었던 날

단순히 평가기간의 모든 달력 날짜를 분모로 사용하지 않는다.

주말/휴일 여부 자체를 임의 추정하지 않고 **기존 일일퀘스트 시스템이 가진 실제 대상/완료 기록**을 기준으로 한다.

## 분자

기존 B.R.A.N.D.에서 그 날짜의 일일퀘스트를 **완료 처리한 날**.

표시 예:

`18 / 20 · 90.0%`

데이터 근거가 없는 날짜를 임의로 완료/미완료로 만들지 않는다.

---

# 12. 업적 데이터

평가기간 동안 **공식적으로 새로 달성한 업적**을 집계한다.

메인 테이블:

- 업적 개수
- 업적 점수 합계
- 업적 종류 요약

예:

> `8개 · 42점 · [상세]`

---

## 12.1 업적 개수

평가기간 안에 공식 달성 처리된 업적의 수.

테스트/취소/무효 데이터 제외.

---

## 12.2 업적 점수

평가기간 안에 새로 달성한 업적들의 공식 업적 점수 합.

현재 업적 마스터의 임의 재계산이 아니라 **해당 달성 기록에 대응하는 공식 점수 기준**을 사용한다.

---

## 12.3 업적 종류

메인 표에는 긴 업적명을 전부 나열하지 않는다.

`상세` 버튼/행 클릭을 통해 학생 상세 모달에서 확인한다.

상세 항목:

- 업적명
- UID
- 등급
- 업적 점수
- 달성일
- 필요하면 카테고리

---

# 13. 길드 점수

학생의 `길드 점수`는 평가기간 동안 **해당 학생이 소속된 길드가 획득한 공식 길드 점수**를 의미한다.

가능하면 공식 길드 점수 이벤트/기록을 기간 필터링하여 계산한다.

현재 총 길드 점수를 그대로 표시하지 않는다.

학생이 평가기간 중 길드를 이동한 이력이 존재한다면:

- 실제 소속 기간에 해당하는 길드 점수만 반영하는 것을 원칙으로 한다.
- 데이터 구조상 과거 소속 시점을 복원할 수 없는 경우 임의 추정하지 않고 명확한 제한 표시를 한다.

---

# 14. 길드 내 개인 기여도

평가기간 동안 학생이 기록한 **공식 개인 기여도 점수**를 합산한다.

현재 누적 기여도 전체를 그대로 쓰지 않는다.

기존 개인 기여도 체계의 공식 기록/이벤트를 source of truth로 사용한다.

상세보기에서는 가능하면 기여도 구성 근거를 보여준다.

---

# 15. 기부량

평가기간 동안 학생이 **실제 기부로 처리한 GOLD 합계**.

포함:

- 공식 기부 기능을 통해 기록된 기부
- 기부로 분류된 공식 거래/기록

제외:

- 소득세
- 균형발전 분담금
- 일반 송금
- P2P 구매
- 경매 지출
- 시장 구매
- 교사 차감
- 기타 세금/수수료

즉 `기부`와 `세금/지출`을 혼합하지 않는다.

---

# 16. 2차직업 서비스 판매 횟수

평가기간 동안 해당 학생이 판매자로서 **정상 완료(COMPLETED)** 한 2차직업 서비스 주문 수.

기준 시각:

`completed_at`

포함:

- 평가기간 안에 완료된 주문

제외:

- REQUESTED
- ACCEPTED
- DELIVERED 상태에서 아직 완료되지 않은 주문
- REJECTED
- CANCELLED
- 무효/삭제 처리된 주문

메인 표에는 건수만 표시.

학생 상세보기에서는 가능하면:

- 서비스명
- 구매자
- 완료일
- 판매금액

을 확인할 수 있다.

---

# 17. 수업 참여 정성평가

교사가 학생별로 직접 입력한다.

항목은 정확히 4개.

1. **수업준비와 책임**
2. **참여와 경청**
3. **과제 수행**
4. **개선과 성장**

각 항목 선택값:

- `S+`
- `S`
- `A+`
- `A`
- `B`

다른 등급을 임의 추가하지 않는다.

---

# 18. 정성평가 점수화 금지

수업 참여 등급을 시스템이 자동으로 숫자로 환산하여 종합점수에 합산하지 않는다.

예:

- S+ = 5점
- S = 4점

같은 자동 환산은 이번 기능에 넣지 않는다.

정성평가는 **교사의 판단 자료**로 사용한다.

---

# 19. 특이사항 / 비고

학생마다 자유 입력 텍스트 영역을 제공한다.

목적:

정량 데이터로 포착되지 않는 내용을 기록.

예:

- 발표 빈도는 낮았지만 모둠원이 막힐 때 지속적으로 설명함
- 월초 대비 과제 수행 태도가 크게 개선됨
- 어려운 상황에서도 책임 역할을 끝까지 수행함

권장 최대 길이:

`2,000자`

자동 공개되지 않으며 교사 전용 데이터.

---

# 20. 예선 12인 선정

메인 테이블 각 학생 행에 `예선 후보` 선택 기능을 둔다.

## 규칙

- 최대 12명
- 12명을 넘겨 선택 불가
- 선택 즉시 상단 카운터 갱신
- DRAFT에서는 자유롭게 변경 가능
- FINALIZED 이후 변경 불가

FINALIZED 조건:

**정확히 12명 선택되어 있어야 함**

# 31. 보안 / 권한

이 기능은 **교사 전용**.

학생 계정은:

- 페이지 접근 불가
- RPC 호출 불가
- 정성평가/비고 조회 불가
- 다른 학생 MVP 기초 데이터 조회 불가

중요 쓰기 작업은 클라이언트 직접 table mutation보다 **teacher RPC**를 우선한다.

RPC는:

- SECURITY DEFINER 필요 시 사용
- fixed `search_path`
- 교사 역할 검증
- 현재 담당 classroom 검증
- 다른 학급 session/student 접근 차단

---

자동 통계 계산과 확정 저장은 서버에서 처리한다.

# 33. 데이터 근거 우선 원칙

통계값은 가능한 한 기존 공식 기록 테이블/이벤트/RPC를 source of truth로 사용한다.

임의 추정 금지.

예:

- BV → 공식 BV 거래/변동 기록
- 일일퀘 → 기존 완료 기록
- 업적 → 공식 달성/부여 기록
- 길드 → 공식 길드 점수 기록
- 기여도 → 공식 개인 기여도 기록
- 기부 → 공식 기부 데이터
- 서비스 → 공식 서비스 주문 완료 데이터

데이터가 기간별로 복원 불가능한 항목은 숨겨서 추정하지 말고 교사에게 `기간별 근거 데이터 부족` 상태를 보여준다.

# 35. 성능

24명 기준이지만 학생별로 별도 RPC를 24번 호출하는 N+1 구조는 피한다.

권장:

- 회차 전체 집계 1회
- 상세보기는 필요 시 학생 1명 단위 지연 로드

복잡한 기간 집계는 서버 SQL에서 처리한다.

---

# 36. 화면 가독성

MVP 선정은 비교 작업이므로 한 화면에서 학생 간 차이가 잘 보여야 한다.

- 숫자는 우측 정렬 권장
- %는 소수점 1자리
- GOLD/BV 천 단위 구분
- 성장률 양수/음수 시각 구분
- 후보 12인은 명확한 체크/배지
- 수업평가 4개는 한 학생 내에서 빠르게 연속 입력 가능
- 긴 비고는 테이블을 과도하게 늘리지 않도록 요약 + 상세 방식 가능

# 37. 평가 등급 UI

수업 참여 등급 선택은 기존 길드 미션 결과 입력 UI와 유사한 즉시 선택형 버튼/세그먼트 방식 권장.
