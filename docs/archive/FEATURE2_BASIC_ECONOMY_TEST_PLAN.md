# 테스트 계획 — 기본 경제 행동

모든 테스트는 실제 운영 데이터 손상을 피하도록 **GOLD 1 또는 최소 교환 단위**로 진행합니다.

## 0. 준비

- 교사 일반 창
- 학생 A 시크릿 창
- 학생 B 다른 시크릿 창 또는 브라우저
- 세 화면 모두 F12 → Network → Fetch/XHR 준비
- 학생 A·B의 GOLD/CRYSTAL 기록
- 현재 복지기금 잔액 기록

## 1. SQL·빌드

1. `20260806_02_basic_economic_actions.sql` 실행
2. 권한 결과 확인
3. 프로젝트에서 실행

```bash
npm ci
npm run build
npm run dev
```

기대:

- TypeScript·Vite build 성공
- 화면 진입 시 400~500 오류 없음

## 2. P2P 단일 송금

학생 A:

1. 내 자산 → 송금
2. 학생 B 선택
3. GOLD 1
4. 메모 `기능 테스트 송금`
5. 확인 후 확정

기대:

- A GOLD -1
- B GOLD +1
- A 거래 `P2P_SEND`
- B 거래 `P2P_RECEIVE`
- 양쪽 화면 새로고침 없이 반영
- `p2p_transfers` 한 행 생성

## 3. P2P 실패 방어

확인:

- 본인 선택 불가
- 다른 학급 학생 미노출 및 서버 차단
- 0·음수·100만 초과 금액 차단
- 잔액 초과 차단
- 메모 2자 미만 차단
- 버튼 연속 클릭 중복 송금 없음

## 4. 교사의 P2P 취소

교사:

1. 학급 운영 → 거래 취소·정정
2. 방금 송금 선택
3. 사유 `기능 테스트 송금 원복`
4. 취소 확정

기대:

- A에게 GOLD 1 환급
- B에게서 GOLD 1 회수
- 원본 송신·수신 거래 모두 `is_reversed=true`
- 취소 거래 2건 생성
- 교사·학생 화면 즉시 반영

실패 방어:

- B가 받은 GOLD를 모두 사용해 잔액이 0이면 취소 실패
- 이때 A에게도 환급되지 않아야 함
- 원본 두 거래 모두 미취소 상태여야 함

## 5. 화폐 교환

학급 비율이 2인 경우 학생 A:

1. 내 자산 → 교환
2. GOLD 선택
3. GOLD 2 사용
4. CRYSTAL 1 수령 확인
5. 확정

기대:

- GOLD -2
- CRYSTAL +1
- `EXCHANGE_PAY`, `EXCHANGE_RECEIVE` 생성
- `exchange_logs` 한 행 생성
- 즉시 반영

반대 방향도 최소 단위로 테스트:

```text
CRYSTAL 2 사용 → GOLD 1 수령
```

## 6. 교환 실패·취소

실패 방어:

- 비율의 배수가 아닌 금액 차단
- 보유량 초과 차단
- BV 선택 불가

교사 취소:

- 교환 대표 거래 선택
- GOLD·CRYSTAL이 정확히 원상복구
- 원본 2건과 취소 2건 연결

받은 화폐를 이미 사용한 경우:

- 취소 전체 실패
- 원래 사용 화폐만 환급되는 부분 성공이 없어야 함

## 7. 복지기금 기부

학생 A:

1. 내 자산 → 기부
2. GOLD 1
3. 메시지 `기능 테스트 기부`
4. 확정

기대:

- A GOLD -1
- 거래 `DONATION`
- `welfare_fund_movements`에 `COLLECT` 1건
- `welfare_funds.current_balance` +1
- 프로필 누적 기부 +1

## 8. 기부 취소

교사:

1. 기부 거래 선택
2. 사유 `기능 테스트 기부 원복`
3. 취소

기대:

- 학생 GOLD +1
- 복지기금 잔액 -1
- 원본 기부 거래 취소 표시
- `REFUND` 기금 원장 생성
- 누적 기부 원상복구

기부금이 이미 분배되어 현재 기금이 부족하면:

- 취소 실패
- 학생 환급 없음
- 기금 원장 변경 없음

## 9. 교사 지급·차감 취소

Feature 1에서:

1. 학생 A에게 GOLD 1 지급
2. 거래 취소·정정에서 취소
3. 잔액 원복 확인
4. 학생 A에게 GOLD 1 차감
5. 취소 후 잔액 원복 확인
6. BV도 같은 방식으로 소액 테스트

정확한 금액으로 정정해야 한다면:

```text
잘못된 거래 취소 → 학생 자산 지급·차감에서 정확한 금액 재처리
```

## 10. 자산동결

테스트용 자산동결 비상사태를 발동한 상태에서:

- P2P 송금 거부
- 화폐 교환 거부
- 기부 거부
- 오류 메시지 `현재 자산동결 상태예요`

테스트 후 비상사태를 종료합니다.
