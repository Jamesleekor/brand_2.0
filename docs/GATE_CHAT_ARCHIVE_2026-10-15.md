# 차원관문 학생 AI 대화 기록

## V2 실행기 경로 수정 (2026-10-15)
첫 CMD는 내장 JavaScript의 역슬래시가 `\b` 제어문자로 평가되어 프로젝트 확인에 실패했다.
V2는 Windows에서도 절대경로인 `C:/brand_2.0/brand_2.0`을 JSON.stringify로 직렬화한다.
최종 CMD에서 추출한 코드의 실제 경로 인자를 대체하지 않고 평가하고, Downloads 기준 Windows 경로 해석 결과를 확인했다.
첫 실패는 package.json 존재 확인 단계이므로 소스 쓰기나 백업 생성 전에 중단됐다. DB 조회 함수는 재적용하지 않는다.

## 적용 상태
- 운영 DB migration `20261015094235_gate_chat_teacher_archive` 적용 완료 (2026-10-15).
- CMD는 프론트 소스·이 문서·이미 적용한 SQL의 로컬 기록만 저장한다. DB SQL을 재실행하지 않는다.
- GitHub main 기준 소스를 바탕으로 제작했다. 사용자의 최신 미커밋 로컬 소스는 제공되지 않았다.
- npm 설치/빌드, 커밋·푸시는 실행하지 않았다.

## 위치와 동작
편린 운영 → 대화 기록. 이 탭에서 상단 편린 통계 카드를 숨긴다.
학생 목록 약 220px, 남은 공간은 문답 본문. 화면 높이에 맞춰 목록/본문만 스크롤한다.
학생·편린·기간·본문 검색, 검색 문답 전후 보기, 최근 20회 및 이전 문답 추가 조회.
테스트 계정은 서버에서 제외한다. 전출 학생의 보관 기록은 조회한다.
날짜는 KST이며 종료일을 포함한다. 내용 검색은 대소문자를 무시하는 리터럴 부분 검색이다.
검색 조건은 학생 발언 또는 연결된 AI 응답에 적용하며, 한쪽만 검색돼도 문답 전체를 표시한다.
문답은 학생 메시지를 기준으로 request_id/학생/편린을 함께 묶는다. 저장된 응답이 없는 경우 표시한다.
학생 메시지가 없는 고아 AI 응답은 문답에 포함하지 않는다. 현재 데이터는 모든 102회가 1:1로 대응한다.

## XLSX
선택 학생 또는 현재 학생 목록 전체. 기간·본문 검색·편린·학생 이름 검색 결과를 적용한다.
화면의 20회 표시 제한과 무관하게 해당 조건 전체를 500회 단위로 읽는다.
첫 페이지 snapshot_id를 후속 요청에 유지한다. 생성 도중 새 메시지는 포함하지 않는다.
응답은 첫 snapshot 시점까지 저장된 것만 포함한다. 정지된 대화·응답 누락은 별도 문구로 표시한다.
20,000회 초과 및 페이지 이상 시 부분 파일을 만들지 않고 범위를 좁히도록 안내한다.
OOXML XLSX ZIP을 앱에서 생성한다. 새 의존성 설치나 외부 서비스 업로드는 없다.
사용자 발언을 수식으로 쓰지 않는다. 메시지는 inlineStr, 날짜는 KST Excel serial 값이다.

## 서버 보안과 부하
- 노출 public RPC는 SECURITY INVOKER wrapper다.
- 잠긴 원본 테이블 조회는 비노출 `brand_gate_archive`의 SECURITY DEFINER 함수가 담당한다.
- 내부/외부 함수에 모두 anonymous/PUBLIC EXECUTE를 제거했다.
- 내부 함수도 auth.uid(), 기존 교사/관리자 역할 및 current_classroom_id()를 매번 검증한다.
- 학생 지정 시 학급·학생 역할·테스트 계정 여부를 서버에서 추가 검증한다.
- 기존 테이블 GRANT/RLS 및 대화 데이터/관계/호감도/일일 제한은 수정하지 않는다.
- 상시 polling 없음. 탭 활성/조건 변경/명시적 새로고침에 조회하며 React Query 캐시를 사용한다.
- 상세 본문은 최근 20회만 최초 반환. 목록 조회는 학생/편린별 집계만 반환한다.
- 새 테이블/트리거/인덱스 없음. 기존 학생·편린·시각 및 요청별 인덱스를 활용한다.

## 검증과 남은 확인
확인: 실제 교사 JWT claim을 트랜잭션 내 설정하고 authenticated 역할로 서버 조회 성공.
확인: 학생13명/문답102회, 테스트 제외, 20+16 페이지, 중복 없음, 앞뒤 문답, KST 기간, 리터럴 검색.
확인: 학생/익명/다른 학급/테스트 학생 직접 조회 거절 및 anonymous EXECUTE 차단.
확인: Node 24의 TypeScript 5.6.3 compiler API로 신규 TS/TSX와 통합 파일 구문 검사를 통과했다.
확인: 최종 CMD의 base64 payload를 추출해 실행. 기준 소스·한글/공백 경로·CRLF/BOM·레이아웃 변형에 적용했다.
확인: 재실행 시 변경 없음, 원본 백업, 프론트 복원, 기존 파일 충돌/미지원 구조에서 쓰기 전 중단.
확인: 실제 102회 문답 및 수식처럼 시작하는 메시지로 XLSX ZIP CRC·모든 XML·한글·문답 수·텍스트 셀을 검증했다.
전체 프로젝트 타입 검사/production build와 실제 교사 브라우저 로그인 E2E, Windows CMD 실제 실행은 미실행.
브라우저 실행 파일이 없어 자동 레이아웃/브라우저 상호작용 검증은 수행하지 못했다.

## 사용자 확인 순서
1. CMD를 어느 폴더에서나 실행한다. 경로는 C:\brand_2.0\brand_2.0 고정이다.
2. 로컬에서 `npm run build`를 실행한다.
3. 편린 운영 → 대화 기록: 학생 전환, 편린, 기간, 본문 검색, 앞뒤 보기, 이전 대화를 확인한다.
4. 선택 학생/현재 목록 전체 XLSX를 열어 조회 범위와 한글 원문을 확인한다.
5. 작은 화면에서 학생 선택·본문·상단 필터가 겹치지 않는지 확인한다.
6. 실패 시 CMD가 출력한 백업 폴더의 RESTORE.cjs를 Node로 실행해 프론트를 복원할 수 있다.
   이후 사용자가 수정한 파일은 복원기가 자동 덮어쓰지 않는다. DB 조회 함수는 기록을 변경하지 않는다.
