# 1인1역 기록실 학생 화면

## 구현과 배포 상태

홈의 기존 ‘나의 1인1역’ 카드 전체를 `/primary-jobs`에 연결한다. 제목 옆 화살표로 진입 가능함을 표시하고 키보드 접근을 지원한다. 전역 메뉴와 운영 화면에는 항목을 추가하지 않는다.

소스 구현과 정적 검증까지 수행했다. npm 설치·production build·개발 서버 실행·commit·push는 실행하지 않았다. 사용자 로컬 build와 배포 후에 실제 학생에게 노출된다. `AGENTS.md`의 Git/빌드 운영 규칙을 따른다.

## 학생 화면

- 월별 담당표: 3~11월 월 선택, 역할명·담당 학생·기본 일급·전월 대비 변화. PC 2열, 모바일 1열 목록이다.
- 역할별 이력: 선택한 역할의 월별 담당자·당시 일급. 사라진 역할도 보존하며 통합 전후 역할은 관련 기록 링크로 연결한다.
- 학생별 이력: 본인 또는 학급 학생·과거 명단의 월별 역할과 일급. 역할명과 일급 사이 간격은 내용 기준으로 좁게 유지한다.
- 역할명·학생 이름을 누르면 해당 탭으로 이동한다. 탭 사이에 선택한 월·검색·정렬을 유지한다.
- 본인 역할 요약, 나의 이력 바로가기, 로딩·오류·재시도·새로고침을 제공한다.

## 현재 운영 자료와 상태

운영 DB `get_primary_job_archive()`의 현재 응답 187행을 그대로 사용한다. 코드에 학생 명단이나 금액을 하드코딩하지 않는다.

- 4월: 정정 후 23명·23개 역할로 확정된 자료를 조회한다.
- 5월: 환경(사물함&신발장) 120 G 기록을 유지한다.
- 6월: 모든 보기에서 ‘기록 분실’로 구분한다.
- 8월: 7월 역할을 이어서 수행했다는 메모를 표시한다.
- 9월·10월: 각 24개 역할의 등록 일급을 조회한다.
- 11월: 23개 역할의 일급을 조회한다. 담당자가 전원 미정인 현재 상태는 ‘담당자 배정 대기’로 표시한다. 시간표 관리&일정 알리미 통합 전 역할로 이동할 수 있다.
- 일급 미등록을 0으로 바꾸지 않는다. 전월 금액이 없거나 기록 분실·통합 등으로 역할이 달라지면 증감을 추정하지 않는다.
- 김지완의 과거 이름 기록을 조회하며 새 계정을 만들지 않는다.

## 조회와 권한

학급과 학생은 기존 로그인 컨텍스트를 사용한다. 실제 데이터 범위는 서버의 로그인 학급 판정과 RLS를 따른다. 클라이언트는 조회 RPC만 호출하며 운영 배정·급여·기록을 변경하지 않는다. Zod로 응답을 검증한다.

학급·학생별 React Query 키에 5분 캐시를 사용한다. 월·탭·검색은 같은 응답으로 전환한다. 포커스 시 stale 응답을 갱신하고 수동 새로고침을 제공한다. 추가 polling이나 Realtime 구독은 만들지 않는다.

## 검증과 후속 확인

AI 검증은 TypeScript 구문 검사, 실제 RPC 응답 Zod 검증, 화면 함수와 이벤트 핸들러 검증, 미등록/기록 분실/11월 배정 대기·전출생·전월 증감 처리, 원클릭 패치 사전 검사와 재적용·CRLF/BOM 호환 검증이다. 실제 브라우저 배치와 사용자 로컬 production build는 미검증이다.

- [ ] 역할명·학생 이름을 눌렀을 때 해당 이력으로 이동.
- [ ] 학생별 표에서 역할명과 일급 사이에 큰 빈 공간이 없음.
- [ ] 6월 기록 분실, 과거 일급 미등록, 11월 담당자 배정 대기 구분.

## 적용

이 전달본은 프론트엔드와 문서만 적용한다. SQL 재실행이나 데이터 재입력은 필요 없다. 10월 22일 초기 UI 패치를 아직 push하지 않은 로컬 작업에도, 초기본과 일치하는 파일만 검증 후 업데이트한다. 사용자 수정으로 다른 파일이 있으면 전체 쓰기 전 중단한다.
