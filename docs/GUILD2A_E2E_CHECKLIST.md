# Guild 2A — 운영 적용 후 확인 순서

이 문서는 개발자가 아닌 운영자도 따라 할 수 있도록 만든 확인표입니다.
Guild 2A는 아직 **월 최종 확정 기능이 아니라 초안 점수 기능**입니다.

## 2026-08-13 실제 확인 결과

다음 항목은 production에서 실제 교사·학생 계정으로 확인되어 통과했습니다.

- Guild 2A Core SQL과 두 후속 수정 SQL 적용
- 첫 초안 계산과 학생별 점수 표시
- `ABSENT` 감점 후 `PRESENT` 또는 `EXCUSED`로 고쳤을 때 점수 자동 복구
- 교사 기여 기록의 공개/비공개 표시와 취소(반대 기록) 처리
- 4인 길드 인원 보정의 적용·해제
- 교사 GS 수동 조정과 기록 보존
- 학생의 자기 점수 조회, 비공개 메모 비노출, 교사 화면 접근 차단

Guild 1의 기존 학생 이동·해제·재배정과 이동 전 세션 snapshot 보존도 production에서 통과했습니다. 다른 기기 사이의 Realtime 즉시 반영과 전입/전출은 별도 확인 항목으로 남습니다.

## 0. 2026-08-13 권한 오류 수정

처음 Guild 2A SQL을 적용한 뒤 다음 오류가 보인 경우가 있습니다.

`infinite recursion detected in policy for relation "guild2_observation_events"`

이 경우 [20260813_01_guild2a_observation_rls_recursion_fix.sql](../supabase/migrations/20260813_01_guild2a_observation_rls_recursion_fix.sql) 전체를 Supabase SQL Editor에서 **한 번만** 실행하세요.

이 파일은 공개 메모를 보여 주는 권한 규칙만 고칩니다. 학생·길드·세션·점수·기여 기록을 삭제하거나 수정하지 않습니다.

또한 2026-08-13에 길드 세션 출석을 수정해도 기존 감점 초안이 바로 다시 계산되지 않는 문제를 확인했다. [20260813_02_guild2a_refresh_after_session_attendance.sql](../supabase/migrations/20260813_02_guild2a_refresh_after_session_attendance.sql)도 SQL Editor에서 한 번 실행하세요. 이 파일을 적용하면 `ABSENT`를 `PRESENT` 또는 `EXCUSED`로 고친 직후 해당 월의 Guild 2A 초안 점수가 자동으로 다시 계산됩니다.

## 1. 먼저 SQL 적용

1. Supabase Dashboard를 열고 해당 프로젝트의 **SQL Editor → New query**로 들어갑니다.
2. [20260812_02_guild2a_core.sql](../supabase/migrations/20260812_02_guild2a_core.sql) 전체를 복사해 붙여넣습니다.
3. Run을 한 번 누릅니다.
4. 맨 아래 결과에 새 `guild2_*` 표와 `teacher_*_guild2_*` 함수가 보이면 구조 적용은 성공입니다.

이 SQL은 다음을 **하지 않습니다**.

- Guild 1 멤버/세션/소속 이력 삭제 또는 수정
- 기존 `guild_gs`, `guild_individual_contributions`의 과거 점수 수정
- Guild 3 미션 또는 Guild 4 동료평가 생성

SQL Editor는 교사로 로그인한 앱 화면이 아니므로, SQL Editor에서 교사용 버튼 RPC를 직접 실행해 보지는 마세요.

## 2. 교사 화면에서 첫 계산

1. 실제 교사 계정으로 앱에 로그인합니다.
2. 주소 `/teacher/guild/scores`를 엽니다. 또는 Guild 1 운영 화면의 **Guild 2 점수** 버튼을 누릅니다.
3. 현재 길드 시즌 안에 있는 월을 선택합니다.
4. **점수 다시 계산**을 누릅니다.

기대 결과:

- 길드별 GS가 `초안`으로 보입니다.
- 미션, 동료평가, 아케이드는 `연결 전`으로 보입니다. 완료된 0점처럼 보이면 안 됩니다.
- 길드 세션을 아직 만들지 않은 달의 세션 점수는 `연결 전`이며, 150점으로 보이면 안 됩니다.

## 3. 길드 세션 점수 확인

Guild 1 운영 화면에서 같은 달에 길드 세션을 하나 만든 뒤, 서로 다른 학생에게 다음 상태를 기록하고 저장합니다.

- PRESENT 학생: 세션 점수 차감 없음
- EXCUSED 학생: 세션 점수 차감 없음
- ABSENT 학생: 30점 차감

저장 뒤 Guild 2 점수 화면을 새로고침합니다. 20260813_02 후속 SQL을 적용했다면 점수는 자동으로 다시 계산됩니다. 그 SQL을 아직 적용하지 않았다면 **점수 다시 계산**을 한 번 눌러야 합니다.

기대 결과:

- 세션 점수는 `150 - (일반 불참 횟수 × 30)`입니다.
- 불참이 5회 이상이어도 음수가 아니라 0점입니다.
- 학생 화면 `/guild`에서 세션 점수와 `일반 불참 N회 × -30` 설명, 세션별 상태를 함께 볼 수 있습니다.

## 4. 교사 기여 기록 확인

1. 교사 Guild 2 화면에서 학생, 분류, 날짜, 짧은 사유를 입력합니다.
2. **기여 기록 저장**을 누릅니다.
3. 해당 학생의 교사 기여 점수가 10점 올라가는지 확인합니다.
4. 같은 달에 총 15건까지 반복한 뒤, 16번째 기록도 남겨봅니다.

기대 결과:

- 기록 1건은 +10점입니다.
- 기록은 16건 이상 남길 수 있지만 점수는 최대 150점입니다.
- 기본 기여도는 아케이드를 제외한 합계입니다.
- 학생에게 공개를 체크하지 않은 메모는 학생 화면에서 보이지 않습니다.
- 공개를 체크한 메모만 학생 화면의 “학생에게 공개된 기여 메모”에 보입니다.

잘못된 기록을 확인하려면:

1. 해당 기록의 **취소**를 누릅니다.
2. 2자 이상의 취소 사유를 넣고 확인합니다.

기대 결과:

- 원래 기록은 사라지지 않고 `취소됨`으로 남습니다.
- 점수에는 더 이상 반영되지 않습니다.
- GS 기록장에는 취소에 따른 반대 기록이 남습니다.

## 5. 4인 길드 인원 보정 확인

1. 대상 길드에서 **인원 보정 대상 길드** 체크를 켭니다.
2. 길드 GS 초안의 인원 보정 금액을 확인합니다.
3. 체크를 다시 끕니다.

기대 결과:

- 켜면 `평균 기본기여도 × 0.5`가 추가됩니다.
- 결과는 10 GS 단위 반올림입니다.
- 아케이드 보너스는 평균에 포함되지 않습니다.
- 실제 현재 인원이 4명인지 여부만으로 자동 켜지거나 꺼지지 않습니다.
- 끄면 기존 보정 기록은 삭제되지 않고 취소 기록으로 상쇄됩니다.

## 6. 학생 화면 확인

학생 계정으로 `/guild`를 엽니다.

- 이달 개인 기여도: 기본 `/900`, 아케이드 `획득 +N / 반영 +M`(반영 최대 +90), 최종은 기본 + 적용 Arcade (최대 990)
- 동료평가, 미션, 세션, 길드 기여 기록, 아케이드의 다섯 카드
- 미션/동료평가/아케이드는 현재 `연결 전`
- 교사 기여 기록의 건수·분류만 보이고, 비공개 메모는 보이지 않음
- 다른 학생의 개인 기여도나 교사용 GS 기록장은 보이지 않음

## 7. 권한과 Guild 1 회귀 확인

- 학생 계정으로 `/teacher/guild/scores`에 접근할 수 없어야 합니다.
- 학생은 교사 기여 기록 저장, 취소, 인원 보정, GS 수동 조정을 할 수 없어야 합니다.
- Guild 1에서 멤버 이동/해제/재배정, 세션 생성/출석 저장이 production에서 통과했습니다.
- 멤버를 이동한 뒤에도 과거 길드 세션의 참가자 snapshot이 유지되는 것을 production에서 통과했습니다.

## 8. 범위 밖 또는 별도 확인 항목

- Supabase Realtime publication이 새 `guild2_*` 표에 켜져 있는지. 꺼져 있어도 저장 직후 화면은 자동 새로고침되지만, 다른 기기에서의 즉시 반영은 확인이 필요합니다.
- Guild 3 Mission, Guild 4 Peer Review, Guild 2B Arcade adapter, Guild 5 월 마감은 이 작업에 포함되지 않았습니다.
- 전입/전출 E2E는 학생 관리 화면이 생긴 뒤에 별도로 확인합니다.
